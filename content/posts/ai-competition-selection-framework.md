AI 赛事的难点通常不在于发现一条公告，而在于判断它是否值得投入。报名页面里的奖金、赛道和截止日期很醒目，真正影响结果的往往是题目匹配度、可交付性与剩余迭代周期。

这篇文章提供一套可复用的筛选框架。它适合 Kaggle、算法赛、Agent 应用赛、开源大赛和黑客松，也适合把已有项目整理成可参赛作品。

## 先确认：这是当前机会吗

每次收集赛事信息时，优先保存官方链接，并用下表做一次核验。第三方资讯可以帮助发现线索，报名状态、规则和时间节点以主办方页面为准。

| 核验项 | 要确认的问题 | 常见误判 |
| --- | --- | --- |
| 报名状态 | 页面是否明确显示可报名、可提交或仍在征集 | 把往届新闻当作本届入口 |
| 截止节点 | 报名、组队、初赛提交、答辩各自何时截止 | 只记录总决赛日期 |
| 交付物 | 需要代码、模型、演示视频、技术文档还是现场答辩 | 做完 Demo 才发现缺少材料 |
| 参赛资格 | 个人、团队、学生、企业和地区是否有限制 | 组队后才发现资格不符 |
| 知识产权 | 是否要求开源、独家展示或授权主办方使用 | 忽略项目后续复用空间 |

把这些信息写进自己的赛事卡片。卡片保持一页以内，包含赛事名称、官方链接、关键日期、所需材料、作品方向和下一步动作。信息需要更新时，只改卡片，不必重新从聊天记录或收藏夹里翻找。

## 用五项评分选出主赛

不要同时追很多赛事。为每个候选赛事按 1 到 5 分打分，再选择总分最高的 1 到 2 场作为主赛。

| 维度 | 5 分信号 | 1 分信号 |
| --- | --- | --- |
| 题目匹配 | 现有技术栈或项目可以直接迁移 | 要从零学习核心技术 |
| 交付可控 | 两周内能完成可演示的最小版本 | 依赖大量外部数据、硬件或审批 |
| 时间余量 | 截止前至少留出一轮评审和重构 | 只能赶出首次提交 |
| 成果复用 | 能沉淀为开源仓库、作品集或业务 Demo | 提交后很难继续维护 |
| 团队互补 | 算法、工程、产品表达有人负责 | 关键角色长期空缺 |

奖金和热度可以作为附加项。它们适合帮助你决定优先级，核心选择仍然来自作品完成概率与长期复用价值。

## 第一周只验证三件事

报名后的第一周决定了项目是否能走到提交。目标是降低不确定性，不是把功能做得很全。

### 1. 跑通最小闭环

先完成一条从输入到输出的完整路径：读取数据、调用模型或算法、生成结果、保存日志。即使效果一般，也要让团队确认任务边界、输入格式和评测方式。

对于 Agent 应用赛，最小闭环可以是“用户问题 -> 检索资料 -> 调用一个工具 -> 给出带依据的答复”。对于算法赛，最小闭环通常是“加载数据 -> 训练基线 -> 生成可提交文件”。

### 2. 提前处理评分规则

把评审标准拆成可验证的任务。若规则强调准确率，就建立固定验证集；若规则强调产品价值，就准备真实场景、用户流程和可量化收益；若规则强调开源贡献，就从第一天开始维护 README、环境配置和许可证说明。

### 3. 确定作品的一句话承诺

用一句完整的话说清楚“谁在什么场景下通过什么能力获得什么结果”。这句话同时约束产品范围、演示脚本和答辩表达。

例如：

> 面向一线客服人员，系统把图文工单转化为带来源引用的处理建议，并将重复查询压缩为一次检索与一次工具调用。

一句话承诺越具体，团队越容易识别功能膨胀。

## 把赛程倒推成四个里程碑

提交截止日通常只是一条硬约束。更可靠的安排是倒推四个内部节点：

1. **MVP 日**：主链路稳定运行，团队可完整演示。
2. **验证日**：完成首轮指标、用户反馈或评审模拟，确定迭代方向。
3. **冻结日**：停止新增大功能，集中修复稳定性、性能和展示细节。
4. **提交日**：在官方截止前预留充足缓冲，完成上传与材料复核。

每个节点都要有可见产物，例如可运行仓库、评测报告、录屏、演示文稿或报名后台截图。只用“继续优化”描述计划，很难判断项目是否真正推进。

## 提交前检查表

- [ ] 官方报名信息、队员信息和联系方式完整一致
- [ ] 代码可在干净环境按 README 复现
- [ ] Demo 覆盖题目要求的核心场景
- [ ] 数据、模型和第三方素材的授权范围已确认
- [ ] 演示视频在无讲解时也能理解问题、过程与结果
- [ ] 技术文档包含架构、关键取舍、局限与下一步计划
- [ ] 提交文件名称、格式、大小和截止时区已复核

## 让一次参赛留下可复用资产

高质量参赛的收益来自赛后沉淀。无论是否获奖，都建议保留三类资产：可复现的代码仓库、可对外讲述的项目案例，以及记录技术取舍的复盘文档。

下一次看到赛事公告时，先完成官方核验和五项评分。选择一个能在首周跑通最小闭环的题目，再用四个里程碑推进。赛事信息会持续变化，团队的判断框架可以长期复用。
