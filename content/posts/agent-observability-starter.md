## 先记录，再优化

Agent 出错时，先回答四个问题：任务在哪里停住、模型花了多久、工具返回了什么、谁确认了结果。为每次运行生成任务 ID，并将每个阶段写入同一条记录。

| 字段 | 用途 |
| --- | --- |
| task_id | 串联一次完整执行 |
| stage | 区分规划、检索、工具调用与生成 |
| duration_ms | 定位耗时瓶颈 |
| outcome | 记录成功、失败和待人工确认 |

## 最小闭环

从一个高频任务开始，例如“读取需求并生成待办”。先保存输入摘要和输出，再接入检索或外部工具。高风险动作保留人工确认点，失败时保存错误上下文与重试次数。

可观测记录会把一次演示变成可复盘的工程系统。下一次优化只选择一个指标：成功率、耗时或人工介入率。
