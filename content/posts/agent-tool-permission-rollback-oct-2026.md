《大学》开篇写「知止而后有定，定而后能静」。把 Agent 接到工单、邮件、数据库和云资源之前，先把「止」写清楚：止于只读，止于白名单，止于人工确认，止于可补偿的写操作。定，才谈得上静；静，才谈得上上线。

本文面向要把 Agent 接到真实系统的工程师、平台负责人和值班负责人。全文只写防御与工程约束：鉴权、白名单、人工确认、补偿事务、只读副本、审计字段、发布门禁、值班复盘。文中表格、数字、事故均为示意，用来对照清单。请以本团队的系统边界、法务意见和官方最新文档为准。

## 一、Agent 的危险来自副作用，不是口才

评测里好看的回答，和生产里一次不可逆的写入，是两类完全不同的风险。口才决定演示是否流畅；副作用决定事故是否发生。Agent 一旦挂上工具，每一次推理都可能变成一次对真实世界的修改。修改邮件草稿还在内部；修改已发送队列、关闭工单、扣减余额、删除对象存储、扩容计算实例，就会离开可撤回的范围。

副作用有四个可观测特征。第一，动作离开模型上下文，进入外部系统。第二，动作改变持久状态。第三，动作可能被其他人、其他系统、监管记录看见。第四，动作在失败或超时之后，外部系统的真实状态与 Agent 自己的信念可能分叉。四个特征里只要出现一个，这次调用就要按写路径治理，不能按聊天补全治理。

把「会说话」当成「会做事」是常见错觉。语言模型擅长生成看起来合理的计划，计划里的动词（发送、关闭、批准、删除、同步）一旦映射到工具，就会变成真实 API。工程上要做的第一件事，是把自然语言里的动词翻译成副作用等级，再决定是否允许调用。翻译工作必须发生在工具网关，不能只发生在提示词里。提示词会被覆盖、被注入、被模型忽略；网关里的拒绝是硬边界。

只读能力可以尽早上线。检索知识库、查询工单摘要、阅读配置副本、生成草稿、给出操作建议，这些动作把不确定性留在文本层。文本层的错误用评审和回归集就能收敛。写能力必须晚于观测、晚于补偿、晚于演练。没有逆向操作的能力，就不要进入工具名单。这是产品决策，也是安全决策。

上线前用三句话做自我检查。第一句：这个工具调用成功之后，外部世界少了什么、多了什么、改了什么。第二句：调用失败、超时、部分成功时，谁负责把世界拉回一致。第三句：三个月后审计员只拿日志，能不能判断当时该不该做、谁批准的、有没有回滚。三句话答不全，工具保持关闭。

副作用还分「对内可见」和「对外可见」。对内可见包括改内部工单状态、写内部评论、更新内部仪表盘。对外可见包括发信给客户、对公网发帖、调用支付、变更云资源、删除生产数据。对外可见的错误会同时触发客服、法务、公关和账单。默认策略是：对内可见可以进入「待确认队列」；对外可见必须经过人工确认，并且确认界面展示完整副作用摘要。

模型的不确定性会放大副作用。同样的用户请求，两次运行可能选出不同工具、不同参数、不同重试次数。因此，生产治理要按「最坏一次运行」设计，不能按「平均一次运行」设计。最坏一次运行会选错工具、重复调用、在超时后重试、把检索到的指令当成授权。防御体系的目标，是让最坏一次运行仍然停在只读或待确认，而到不了不可逆写入。

《礼记》说「君子慎始」。Agent 项目的始，是工具表的第一行。第一行如果是「发送」「删除」「扣费」，后面所有观测都在还债。第一行如果是「查询只读副本」「生成草稿」，后面每加一个写工具，都可以要求补偿、幂等、确认和演练。顺序本身就是安全控制。

把演示成功当成生产就绪，是副作用治理里最贵的捷径。演示环境允许模拟成功，界面加水印，日志打 `env=demo`。评测集允许用假收件人、假工单、假云项目。生产环境禁止模拟，禁止共用演示密钥，禁止把评测流量打进真实客户通道。口才可以在演示里尽情发挥；副作用只能在生产网关里按级别通行。

团队讨论时，建议把「模型会不会做对」和「做不对时世界会怎样」分成两个议程。前一个议程属于评测、提示词、检索质量；后一个议程属于本文。两个议程混在一次会上，写权限往往会以「准确率已经很高了」的理由被打开。准确率是文本层指标。副作用是系统层指标。系统层没有补偿，文本层分数再高也撑不住一次未知超时。

## 二、权限分级：读、写、付费、外网、删除

权限不要按部门或按模型品牌切，按副作用切。建议至少五级。级别是工具网关的强制属性，模型不能改，提示词不能改，应用层角色可以收窄、不能放宽。

**L0 读。** 查询只读副本、检索文档、读取工单摘要、读取监控指标、读取配置的只读视图。允许自动执行。超时后可有限重试。结果进入上下文前要做脱敏与长度截断。L0 仍有配额：每任务查询次数、返回行数、字段集。配额用尽后降级为基于已有上下文生成草稿，或结束任务并告警。

**L1 写（内部、可逆）。** 在内部系统创建草稿、添加内部评论、写入「待处理」状态、保存生成结果到草稿表。允许进入待确认队列，低风险场景可由值班策略自动通过，但必须可撤销。撤销路径在注册工具时一并提交。L1 的典型补偿是删除草稿、回退状态、标记评论作废。

**L2 付费。** 调用会产生账单的 API、创建计费云资源、触发短信与邮件的计费通道、采购类接口。默认拒绝自动执行。必须有预算上限、单价上限、次数上限，以及财务或技术负责人确认。确认记录进入审计日志。L2 的补偿是退款工单、销毁编排、停止计费通道。退款权限留在财务系统，Agent 最多创建退款申请草稿。

**L3 外网。** 访问公网、发送外部邮件、调用第三方 webhook、向客户可见渠道发消息。默认拒绝。域名、收件人域、通道都走允许列表。内容先入草稿。对外发送的补偿往往只能是更正声明或撤回请求，因此确认门槛高于 L1。L3 与 L2 经常重叠，例如计费短信，按更高的控制执行：既要预算，也要外网确认。

**L4 删除与高危变更。** 删除数据、删除云资源、关闭账号、修改权限、生产 schema 变更、不可撤回的对外法律承诺。默认永久拒绝自动执行。只允许人工 runbook 或工单系统里的受控变更流程。Agent 可以起草 runbook，不能直接执行。L4 出现在 Agent 可调用列表，视为门禁失败。

矩阵要进代码，不能只进文档。工具注册接口至少包含：`level`、`default_deny`、`requires_approval`、`compensation_ref`、`idempotency_required`、`retry_policy`、`budget_policy`、`audit_fields`。缺 `compensation_ref` 的 L1 及以上工具，注册失败。缺预算策略的 L2 工具，注册失败。出现在 L4 的能力，注册接口直接返回拒绝，引导到变更系统。

账号也要分级，工具级别和账号级别取更严的那个。只读副本账号不能拥有写权限。预发账号不能拿到生产密钥。演示账号的「成功」可以是模拟成功，生产账号禁止模拟。一人一号、一环境一号、一任务一短时令牌，这三句话要写进接入规范。

把级别暴露给模型当「建议」没有用。模型会在着急完成任务时自行解释「这次删除其实是清理，可以算 L1」。级别判断发生在网关：根据工具名、参数形状、目标资源和预估账单，计算级别，再套策略。模型只看到允许它看的工具列表。列表随任务类型变化，客服摘要任务看不到支付工具，运维问答任务看不到发信工具。

同一动词在不同对象上级别不同。「删除」草稿是 L1，「删除」生产对象是 L4。「发送」到内部邮箱是 L1 或受控 L3，「发送」到客户域是 L3。「创建」内部待办是 L1，「创建」计费实例是 L2。网关按对象分类器升级级别，分类器的规则可评审、可测试。测试用例用示意对象覆盖升级路径，保证「看起来像内部」的外部对象被升到 L3。

级别还可以随上下文升级，不能随上下文降级。批量、营业外时间、新账号、高额、首次对某客户发言，这些条件只升不降。降级只能走变更单。这能避免模型用「用户说很急」把 L3 降成 L1。

## 三、默认拒绝与白名单

默认拒绝是工具网关的第一行代码。未知工具、未知参数、未知目标、未知环境，结果都是拒绝，并写审计。允许列表是显式的、可评审的、可过期的。过期的允许项自动失效，需要重新申请。这能避免「三年前为演示开的权限」在今天的生产里继续生效。

白名单至少有四层。第一层是工具名。任务类型映射到工具集合，集合外的调用在网关被丢弃。第二层是资源标识。表名、索引名、工单队列、对象前缀、云项目、命名空间，都要匹配允许模式。第三层是网络出口。域名、协议、端口走出站代理的允许列表；解析到内网、链路本地、元数据地址的请求直接拒绝。第四层是身份。调用所用的服务账号、角色、令牌受众必须与任务类型绑定。

参数校验是白名单的一部分。模型生成的参数先走 JSON Schema，再走业务允许列表。路径规范化之后再匹配前缀。收件人检查域，不检查自由文本是否「看起来像内部」。金额检查上限和币种。批量大小检查硬上限，模型写「稍微多删一点」不会变成全表扫描。枚举字段只接受注册过的值，自由字符串字段设置最大长度与字符集。

默认拒绝还要覆盖「工具组合」。单个 L0 工具安全，不等于一串 L0 工具安全。连续检索可能拼出完整密钥材料；连续查询可能拼出个人敏感信息。因此 L0 也要有：字段级脱敏、结果截断、禁止回传密钥形状、按任务的查询次数上限。组合风险用策略引擎表达，例如「同一任务内对用户表的明细查询不得超过约定次数」，次数由隐私负责人和数据负责人共同签字。示意中的具体数字需要按数据分级另行规定。

白名单的变更本身是写操作。新增工具、放宽资源模式、延长令牌有效期，走变更单，包含：申请人、任务类型、有效期、补偿方案、回滚演练记录、观测指标。变更单合并前，安全与值班各一人确认。生产放宽权限禁止在聊天里口头批准。

与默认拒绝配套的是明确的拒绝回执。返回给模型的应是结构化错误：`denied`、原因类别（工具不在列表 / 资源不在列表 / 需要确认 / 预算不足 / 级别不足）、下一步允许的动作（改用只读工具、提交确认、结束任务）。回执避免包含可被用来探测内部结构的细节。模型拿到拒绝后，只允许转向只读路径或结束，不允许改参数对同一高危工具死磕。连续拒绝达到阈值，任务锁定写路径。

环境隔离是白名单的物理层。开发、预发、生产的工具端点、密钥、数据集、收件人列表全部拆开。预发可以用脱敏数据与模拟发信。生产的发信网关在预发密钥下不可达。演示环境允许「假装发送成功」，并在界面水印中写明模拟。

白名单要可测试。每个允许模式配正例与反例，反例包括：错误环境、错误前缀、错误域、过期项、已吊销角色。测试在 CI 运行。模式变更必须带反例，否则视为未完成。网关的单元测试覆盖「默认拒绝」本身：未注册工具、空参数、缺环境字段，均拒绝。

出站解析要在代理内完成。应用自己解析后再请求，容易把允许列表变成字面主机名比较。代理做解析、做端口限制、做协议限制，并把目标域写入审计。IPv6、跳转、多 CNAME，都以代理策略为准。应用层只看见「允许或拒绝」，看不见自由连接能力。

临时放宽要有自动回收。事故夜临时打开某条域名或某张表，必须带过期时间，到期收回，并在值班群留下回收回执。永久放宽走变更单。临时放宽的观测单独成仪表盘，防止「临时」变成默认。

## 四、每一种写操作必须有逆向或补偿

写操作的准入条件是补偿。补偿在工具注册时提交，格式与正向操作同等正式：名称、接口、权限、超时、幂等键、审计字段、失败后的人工步骤。没有补偿文档的写工具，网关拒绝注册。补偿做不到技术自动完成时，必须有时限明确的人工补偿工单模板，模板里写清联系人、数据源、验收标准。

补偿分三类。第一类是真正的逆向：状态从 B 回到 A，对象从删除进入回收站再恢复，权限从授予到撤回。第二类是等效补偿：邮件已读无法收回，发送更正信并记录；扣费成功后走退款；错误关闭的工单再打开并注明原因。第三类是隔离与止损：无法恢复时，切断继续扩散的路径，冻结相关账号，停止后续自动执行，保留现场。三类都要在注册表里标明，不能到事故夜再发明。

补偿必须可执行，不能只可阅读。把「联系管理员处理」写在 Markdown 里，值班同学在凌晨找不到命令。可执行意味着：预发演练过、权限在值班角色里、输入是审计日志里已有的字段、输出有验收查询。验收查询同样走只读副本，例如「该对象在回收站」「该工单状态为变更前值」「该扣费单为已退款」。

补偿有窗口。对象存储的版本恢复、邮件服务商的撤回、云资源的删除保护，都有时间与条件。窗口要写进工具卡，确认界面要展示「超过约定时间后只能走人工补偿」。Agent 的自动重试不得把操作推到窗口之外还假装可逆。超时策略与补偿窗口一起设计。

分布式系统里的写很少是单步。一次「关闭工单并通知用户」可能包含：改状态、写评论、发邮件、更新检索索引。补偿要按编排来想：每一步有自己的补偿，总补偿按相反顺序执行。任一步失败，状态机停在「部分完成 / 待补偿」，禁止标记为成功。状态机的合法落点只有：未执行、待确认、已执行、补偿中、已补偿、人工接管。成功是已执行且验收查询通过。

补偿与正向操作使用不同的幂等键或明确的补偿标记，避免去重表把恢复当成重复伤害而挡住。补偿失败进入人工接管，并保持「补偿中」，禁止假装已恢复。人工接管的工单模板预填 task_id、downstream_ref、before_ref。

下面是回滚清单。清单用于工具评审、预发演练和发布门禁。任一项为否，对应写工具保持关闭。

**回滚清单（上线前逐项签字）**

1. 正向操作的目标资源、账号、环境已写明，生产与预发拆分。
2. 逆向或补偿操作已注册，接口与权限可被值班角色执行。
3. 补偿在预发用真实工具链演练过，留有任务 ID 与日志链接。
4. 补偿窗口与超时、重试策略一致，超时后进入人工接管。
5. 多步写操作有步骤表，失败时进入「部分完成 / 待补偿」。
6. 幂等键在正向与补偿两侧都生效，重复提交不会重复伤害。
7. 确认界面展示副作用摘要、影响对象、不可逆提示、补偿窗口。
8. 审计日志含前后状态或等价快照引用，三个月内可按任务 ID 回放。
9. 只读验收查询已写好，补偿完成后用只读副本核对。
10. 对外可见操作备有更正模板与客服口径，法务审过示意模板。
11. 付费操作备有退款或销毁路径，预算与告警已接值班。
12. 删除类操作默认关闭；若业务强制需要，走变更窗与双人，回收站或版本开启。
13. 回滚演练角色包含：执行人、确认人、观察员，三人职责分离。
14. 演练失败的记录进入回归集，修复前禁止扩大权限。
15. 清单签字人包括：功能负责人、安全、值班负责人。
16. 未知结果有只读核对剧本，核对完成前不标成功。
17. 补偿权限与正向权限分离，补偿角色不能顺便获得更宽的删除权。
18. 对外补偿（更正信、公告）本身也是 L3，走确认与模板。
19. 数据备份与恢复的 RPO/RTO 以组织备份制度为准，Agent 项目引用该制度，不另发明。
20. 清单与工具注册表自动对账，表有工具、清单无签字则拦截发布。

「没有逆向操作就不要给写权限」是清单的压缩版。压缩版适合写在工具表表头。展开版适合写在发布检查单。两份不一致时，以更严的为准。

补偿设计会逼出产品真相。如果某写操作找不到任何补偿，往往说明它本就不该自动化。对外法律承诺、不可逆公开声明、永久删除无版本的数据，这些动作留在人工变更流程里，Agent 做起草与检查清单，人来执行。工程上的谦虚，是承认有些动词没有安全的过去式。

## 五、幂等键、去重、重试风暴

Agent 会重试。模型超时会重试，网关超时会重试，编排器觉得「好像没成功」会重试，用户重复点发送会重试。写路径上的重试是事故放大器。防御的核心是幂等键与去重表，以及「写工具禁止自动重试」。

幂等键在任务创建时生成，绑定 `task_id`、工具名、规范化后的关键参数。发信的关键参数包括模板、收件域、业务对象 ID；扣费包括金额、币种、账户、业务单号；工单变更包括工单 ID 与目标状态。键的生命周期长于最长重试窗口。下游若支持幂等头，原样传递；下游不支持，就在本侧去重表拦截。

去重表记录：键、首次请求时间、最终状态、下游引用 ID、请求指纹。第二次相同键到来时，返回第一次的结果，不再打下游。状态是「处理中」的键，后续请求等待或返回「处理中」，禁止并行打出两笔。去重表的存储要能在网关多副本之间共享，进程内内存去重挡不住水平扩展。

写工具的自动重试默认关闭。需要重试时，生成新的确认单，由人类或策略引擎批准。新确认单使用新的幂等键，或明确声明「这是对同一业务对象的补偿」。把补偿写成原操作的重试，会让去重表挡住真正的恢复。

重试风暴来自循环：模型看见失败，立刻再调用；编排器看见超时，立刻再调度；告警系统看见积压，再拉起更多副本。每层都要有刹车。模型侧：同一工具连续拒绝或失败达到阈值，任务转为人工接管。网关侧：按任务、按工具、按账号的速率限制。编排侧：并发上限、队列深度上限、熔断。下游侧：自己的限流与幂等。四层同时在，一层失效时其他层仍能把伤害关进预算。

超时与成功的定义必须苛刻。只有下游返回明确成功，并且本侧验收查询通过，才能标成功。超时、连接断开、网关 5xx、未知状态，一律标「未知 / 待核对」。未知状态禁止自动重试正向写，只允许只读核对或人工确认后的补偿。把未知当失败再重试，是重复发信和重复扣费的典型路径。

读路径的重试可以宽松一些，但仍要有次数与间隔。检索风暴会打满向量库、跑光配额、把敏感片段反复拉进上下文。L0 也要有每任务查询上限。上限触发后，任务应降级为「基于已有上下文生成草稿」，或结束并告警。

幂等键要进审计日志，也要进确认界面。值班同学看到「与十分钟前的键相同，已去重」才能判断系统在保护。产品上把去重提示写清楚，能减少有人绕过网关直接调下游的冲动。绕过网关的调用，在发布门禁里属于严重项。

规范化是幂等的前提。参数字段顺序、空白、默认值、别名，都要在算键之前变成同一形状。否则模型两次提议「同一个工单关掉」，只因字段顺序不同就打出两枪。规范化规则与工具 schema 一起版本化。schema 变更要评估旧键是否仍有效，必要时在变更窗清空或迁移去重表，并短暂关闭对应写工具。

用户重复提交也要去重。界面用客户端请求 ID，网关映射到幂等键。刷新页面、回放聊天、多端同时点确认，都应落到同一键。确认按钮在处理中禁用。处理中的状态对用户可见，避免以为没点上再点一次。

对账作业是去重的后盾。每日用只读接口核对：有下游引用但无审计、有审计标成功但下游不存在、同一业务单号多笔成功。三类都告警。对账发现的重复伤害，走补偿工单，不走模型当场再试。

熔断条件要预先写死。示意条件包括：未知结果率升高、下游错误率升高、去重命中异常模式、预算消耗速度异常。熔断动作是关闭该工具的自动执行与确认放行，保留只读。熔断恢复走人工，观察一个时间窗后再开。自动恢复会把风暴接回来。

## 六、密钥与工具凭证

Agent 进程里不应长期存放生产写权限密钥。密钥留在专用密钥管理系统，网关在需要时领取短时令牌。令牌绑定任务 ID、工具名、资源范围、过期时间。用完即废，过期即废，任务取消即废。演示环境和评测环境领取的是模拟凭证或预发凭证，领取逻辑用环境变量与账号隔离保证，禁止「同一密钥打所有环境」。

最小权限在凭证层落地。只读任务领取只读角色。草稿写入领取草稿表角色。发信领取只能打出发信网关、且收件域受限的角色。云资源领取只能在指定项目里创建指定规格的角色。删除与授权类角色不出现在 Agent 可领列表。一个人用个人账号把高权限令牌贴进配置文件给 Agent 用，等于绕过全部分级。

密钥泄漏的防御按「假设上下文会被模型复述」来设计。工具返回值、检索片段、错误信息、堆栈，都可能进入下一轮提示。因此：密钥与会话令牌在进入模型上下文前脱敏；错误信息去掉连接串；调试日志与模型上下文分通道；生产禁止把完整 HTTP 头回传给模型。系统提示里也不要放密钥。密钥不进提示词，进网关。

凭证轮换与吊销要能按任务和按角色操作。发现异常调用，先吊销该任务令牌，再吊销该角色，再决定是否吊销上游主密钥。吊销步骤写进值班手册，演练时真的执行一次（在预发）。只在文档里写「联系安全同学」不够。

第三方工具的密钥同样纳入清单。邮件服务商、工单 SaaS、云厂商、向量库、对象存储，每个下游一个独立凭证，避免一张万能键。下游侧能开的 IP 允许列表、回调签名、权限范围，全部打开。Agent 侧能开的出站代理、域名允许列表，全部打开。两边同时收紧，单边失效时仍有一层。

开发者笔记本、CI、演示容器是常见泄漏面。CI 日志默认脱敏。演示容器无生产网络路径。笔记本用个人只读凭证，生产写操作只走网关。代码评审检查：是否把密钥写进提示模板、是否把生产连接串写进示例、是否在客户端暴露管理端点。这些检查进发布门禁，比事后在模型输出里搜密钥形状更稳。

凭证相关的观测指标包括：领取次数、拒绝次数、过期使用次数、跨环境领取尝试、短时令牌实际调用范围是否超出绑定。超出绑定的调用一律拒绝并告警。指标进值班看板。假设性的告警阈值由安全与平台共同设定，本文不给可被误抄的数字。

令牌绑定要可验证。网关在调用下游前核对：令牌的 audience、scope、task_id、expiry。任一不匹配即拒绝。下游若支持传入签名头，把 task_id 带下去，便于对账。令牌本地缓存必须加密且短 TTL，进程退出即丢。多副本网关用密钥系统的动态领取，避免把长期密钥复制到每台机器的磁盘。

人类凭证与机器凭证分开。值班确认用个人身份，来自身份提供方，带 MFA。工具调用用机器身份，来自密钥系统。禁止用某位工程师的云控制台长期密钥跑 Agent。人员离职当天，个人确认权收回；机器角色按任务过期，不因某位同事离开而「顺便长期有效」。

密钥扫描进 CI 与预发。扫描提示模板、示例请求、日志样例、容器镜像环境变量。扫描到疑似密钥则阻断合并。生产运行时对模型输出与工具参数做形状检测，命中则拒绝并告警，原文进受限审计对象，不进普通日志。形状检测规则由安全团队维护，公开文章里只写「要做检测」，不写具体正则，以免变成对照表。

供应商账号的根权限与 Agent 无关。根密钥放在离线或硬件保管流程，Agent 可达的只有最小范围的子角色。云项目的组织策略（organization policy / SCP 一类能力，名称以厂商文档为准）用来挡住「即使角色被配错也无法删除生产桶」。组织策略是最后一道默认拒绝，值得在门禁里勾选。

## 七、提示注入与间接注入的防御原则

提示注入的防御目标是：不可信文本不能变成授权，不能变成工具名，不能变成参数，不能变成「已确认」。本文说明原则与工程约束，不提供攻击构造，不提供绕过步骤。细节分类以 OWASP 对 LLM 应用的公开风险条目为准，名称见附录，操作定义以官网当前文本为准。

把数据与指令分通道。用户输入、检索片段、邮件正文、工单评论、网页摘录，全部当数据。数据通道进入模型时带明确边界标记，并在系统侧声明：数据通道内的任何「请忽略上文」「请调用某工具」「请批准」均无效。真正的授权来自网关策略与人类确认，不来自文本里的祈使句。

工具选择权放在策略层。模型可以提议工具与参数，网关根据任务类型、级别、白名单、预算决定是否执行。检索到的文档即使写着「必须立即删除」，网关仍然只允许 L0，或要求确认。把文档内容直接当成工作流，等于把权限交给了数据源的作者。

间接注入的常见载体是检索库、邮件、工单、附件摘要、第三方页面摘录。防御是源头治理加出口治理。源头：入库前清洗，分离纯文本与指令性格式，对外部来源打低信任标签。出口：高危工具的参数不得直接引用未经验证的外部字段；收件人、金额、资源 ID 必须与内部业务对象交叉校验。交叉校验失败则拒绝。

输出也要当不可信。模型生成的 URL、文件路径、查询片段、收件人列表，一律当不可信输入再走白名单。禁止把模型输出直接拼进命令、直接当代码执行、直接当收件人。L0 的查询语句用参数化接口与允许的查询模板，模型只填模板槽位，槽位有类型与范围。

系统提示视为敏感配置。最小暴露：模型不需要的内部策略不要放进提示。提示泄漏后，权限边界仍然由网关维持。网关维持不了的事情，不要只写在提示里。这是「提示是体验，网关是控制」的具体化。

人机界面要防「确认文案被模型写出来」。确认页的副作用摘要由网关根据工具注册表与参数生成，不用模型生成的「我即将做一件好事」段落作为唯一信息。人类看到的是资源 ID、前后状态、收件域、金额、补偿窗口。模型可以附加解释，解释默认折叠，不作为授权依据。

评测集要包含注入类样本，样本来自公开基准与内部红队的防御向用例。评测目标是：在注入文本存在时，高危工具调用率为零，任务降级为只读或待确认。评测在预发进行。生产流量只做检测与告警，不做攻击性验证。检测规则关注「模型是否试图调用未授权工具」「确认摘要与实际参数是否一致」，由安全团队维护。

对员工培训只讲防御动作：不要把未知文档直接当指令，不要在系统提示里放密钥，不要关闭网关「图个方便」，发现异常拒绝率升高时先停写工具。培训材料同样不包含攻击教程。

信任标签随数据流动。内部工单评论、外部邮件、公开网页、用户粘贴的长文本，四类来源进入检索或上下文时带不同信任级。低信任来源禁止直接填充 L1 以上参数槽。需要引用时，只引用已经与内部主键对上的字段。对不上的字段可以出现在给人类看的解释里，不能出现在网关执行的参数里。

多 Agent 接力时，上游输出对下游仍是数据。Planner 的自然语言计划，不能直接变成 Worker 的授权。Worker 只接受网关签发的任务令牌与工具列表。把上游的「请继续删除」当成下游的批准，注入会在接力中放大。接力协议里应有：任务类型、允许工具、资源范围、确认状态。缺确认状态的写任务，Worker 拒绝执行。

浏览器类、连接器类工具默认按 L3。页面内容、第三方 SaaS 记录，都是间接注入的宽入口。能用官方 API 与字段白名单完成的，不用通用浏览。必须浏览时，只抽取可见文本，剥离脚本与隐藏指令块的处理在安全可控的解析器里做，解析器输出纯文本数据通道。具体解析实现以内部安全规范为准，本文只要求「浏览结果当数据」。

发现疑似注入时的运行时动作是降级：关闭该任务写路径，保留只读，通知值班，保留上下文到受限对象供事后分析。分析在隔离环境进行。生产网关保持默认拒绝。运行时动作写进手册，避免值班在现场与模型辩论「你是不是被注入了」。辩论没有开关有效。

## 八、人工确认点设计

确认点是把不确定性挡在副作用之前的闸门。闸门太少，事故直达生产；闸门太多，人人点「通过」，闸门失效。设计确认点，是在风险与注意力之间做预算。

确认发生在网关之后、下游之前。模型提议，网关校验级别与白名单，生成确认单，人类看到确认单再放行。确认单字段由系统填：任务 ID、工具名、级别、规范化参数、影响对象、副作用摘要、补偿路径、补偿窗口、预算占用、申请人（模型任务）、建议操作人。模型生成的自然语言解释可附上，但确认按钮绑定的是结构化字段的哈希。字段被改，哈希变，确认作废。

按级别放确认策略。L0 默认不确认，异常查询模式可抽检。L1 默认确认，内部低风险可在工作时间由策略自动通过，夜间与批量仍确认。L2、L3 默认确认，可要求双人：提议人与批准人分离。L4 不进 Agent 确认流，进变更系统。策略用配置发布，变更走门禁。

确认界面要让人能拒绝。拒绝是一等公民：原因必填（选类别：范围不对 / 对象不对 / 时机不对 / 预算不对 / 其他），拒绝后任务进入只读或结束，禁止立刻用同一参数再弹一次。反复弹窗等于逼人点通过。同一任务的确认失败达到阈值，锁定写路径，通知值班。

确认有时效。过期确认单作废，需重新生成，重新展示当前状态。工单可能已被他人处理，余额可能已变，资源可能已不存在。确认时展示「生成后到现在」的只读快照差异。人类批准的是此刻的世界，不是十分钟前的世界。

移动端与聊天里的确认更容易被误点。高危级别要求在工作台完成，工作台有完整摘要与阻断式核对（例如输入资源 ID 末四位）。聊天里的一键通过只开放给 L1 的窄场景，并有日限额。产品为了「体验丝滑」把 L3 做成一键，等于取消确认。

确认人的身份来自企业身份提供方，绑定值班表。谁可以确认哪类工具，是授权矩阵的一部分。开发者本人不得确认自己用个人令牌发起的生产写操作。演示账号不得确认生产。离职与换岗当天，确认权收回。

确认本身要被审计，也要被观测。指标包括：确认等待时长、通过率、拒绝率、过期率、同一人通过量、营业外时间通过量。通过率长期接近百分之百，说明确认已形式化，需要收紧范围或增加抽检。拒绝率突然升高，优先查工具描述、检索质量、任务分流，再查是否有注入导致乱提议。

把确认当成「让人替模型背锅」会失败。确认人必须有能力判断摘要。给客服值班看云资源销毁确认，是错误的角色设计。确认人培训用预发工单，不在生产上练手。

策略自动通过必须可追溯。自动通过时 `approver_id` 记策略名与版本，仍写审计。自动通过的范围用正面列表：指定队列、指定模板、指定工作时间、指定金额上限。超出列表立即回到人工。自动通过的回放能回答「当时哪条规则放行的」。规则变更走门禁，与工具变更同等对待。

确认单要展示「不做」的后果与「做」的后果。只展示做的好处，人会偏向通过。展示对象的当前状态、最近人类操作、是否已有进行中的变更，能减少重复关闭与重复发信。只读快照在生成确认单时冻结一份，批准时再刷新差异。差异过大则作废重来。

双人确认的顺序是：第一人核对对象与参数，第二人核对级别与补偿窗口。两人用同一份哈希。一人既提议又批准，系统拒绝。紧急通道可以缩短等待，不能取消第二人，除非制度里另有事故指挥官角色，且该角色的每次动用事后复盘。

确认队列要有 SLA 与降级。长时间无人确认，任务进入过期，写路径关闭，用户看到「已转为人工处理」。用「超时自动通过」完成 SLA，会把确认变成延迟炸弹。SLA 的正确实现是超时升级到下一值班人，最终升级到关闭写路径并人工接管。

## 九、审计日志最小字段

没有审计，回滚是猜测，复盘是故事。审计日志的目标是：三个月后，不靠当事人记忆，也能回答「当时发生了什么、谁批准的、世界变成了什么样、有没有补回来」。

最小字段建议如下。字段名可按团队规范调整，语义要对齐。

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| event_id | 本条日志唯一 ID | 不可变 |
| task_id | 一次用户任务 | 串联规划、工具、确认、补偿 |
| span_id | 单次工具尝试 | 重试各有 span |
| parent_span_id | 编排关系 | 多步写用 |
| time_utc | 事件时间 | 同时存时区 |
| actor_type | model / human / system | 谁发起 |
| actor_id | 服务账号或人员 ID | 人员来自 IdP |
| env | dev / staging / prod | 严禁串环境 |
| tool_name | 注册名 | 与白名单一致 |
| tool_level | L0–L4 | 当时计算值 |
| decision | allow / deny / pending / expired | 网关结果 |
| reason_code | 拒绝或待确认原因类别 | 对模型可给类别 |
| param_fingerprint | 规范化参数哈希 | 原文按分级存储 |
| resource_ids | 目标对象 | 工单、对象键、实例 |
| idempotency_key | 去重键 | 可空于纯读 |
| approval_id | 确认单 | 无则空 |
| approver_id | 确认人 | 策略自动通过也要标记 |
| downstream_ref | 下游返回 ID | 邮件 ID、支付单号 |
| outcome | success / unknown / failed / compensated | 未知单独成类 |
| before_ref | 变更前快照引用 | 对象存储或状态 |
| after_ref | 变更后快照引用 | 验收用 |
| compensation_ref | 补偿任务 | 可空 |
| token_id | 短时令牌 | 便于吊销追溯 |
| budget_delta | 预估或实际费用 | L2 必填 |
| trust_source | 数据来源信任级 | 注入分析用 |
| hash_chain | 与上一条校验 | 防篡改可选 |

参数原文不一定全量入库。个人敏感信息、密钥形状、邮件正文，按数据分级存摘录或加密对象，日志里留指纹与对象引用。审计员凭权限去对象库看全文。模型调试通道与审计通道分开，调试默认短留存，审计按合规留存。

日志先写后调用。至少在调用下游之前落下「即将执行」事件，调用之后落「结果」事件。只有结果没有即将执行，事故时无法区分「没打出去」和「打出去但没记上」。写日志失败时，写路径应失败关闭，不能「日志系统挂了就先放行」。

查询体验决定日志有没有用。值班至少能按 `task_id` 拉出时间线，按 `resource_ids` 查最近变更，按 `decision=deny` 看拒绝峰值。时间线导出为只读页，供复盘。生产审计库的写账号与 Agent 运行账号分离，Agent 不能删审计、不能改历史。

时钟与一致性。多机用时间同步，时间字段用 UTC，展示用东八区。乱序到达的事件以服务器接收时间与事件时间双记。补偿事件必须能指回原 `span_id`。一场事故的「完整故事」是原操作、确认、下游引用、补偿、验收查询五段，缺一段就补一段只读核对。

留存与访问。审计属于高敏感。访问记审计（查日志这件事本身也记）。导出审批。与法务、安全共同定留存期，本文给原则：足够覆盖内部复盘与适用的监管要求，过期按策略销毁。具体天数以组织制度为准。

完整性可选但值得做。哈希链或外部只追加存储，能提高事后否认的成本。至少做到：存储层只追加、删除要走独立流程、管理员操作另记。Agent 服务账号对审计库只有创建权限。

采样策略：L1 以上全量。L0 可采样，但拒绝、脱敏命中、配额用尽要全量。事故相关 task_id 一旦标记，自动把该任务的 L0 补拉到全量保留。采样配置变更走门禁，因为采样等于选择遗忘。

字段字典要版本化。新增工具同时新增必填字段对照。对照失败则工具注册失败。这能避免「新发信工具忘了记收件域」。每周一次用只读查询找空字段率，空字段率升高说明新代码绕过了网关或 schema 没更新。

## 十、回滚演练

补偿写在文档里，等于没有。演练把补偿从句子变成肌肉记忆。没有演练记录的写工具，发布门禁视为未就绪。

演练在预发做，用与生产同构的工具链、脱敏数据、模拟外网通道。生产演练只在变更窗、有回退方案、有观察员时做，且范围极窄。Agent 项目早期，预发演练足够拦住大多数设计缺陷。

一次最小演练包含：正向写入、故意失败、补偿、验收、日志回放。故意失败的方式用配置开关模拟下游超时或返回未知，避免在生产制造真实伤害。观察员记录：状态机是否停在待补偿、确认是否再次出现、幂等键是否挡住重复正向、验收查询是否只走只读副本。

角色分离。执行人跑工具，确认人批确认单，观察员对照清单。三人不能是同一会话里的同一个「管理员万能号」。演练也是在练权限分离。发现有人用生产密钥打预发，视为演练失败。

演练频率与范围。新工具上线前至少一次全路径。存量 L2/L3 工具按发布周期抽检。补偿窗口会过期的能力（撤回、回收站）要在窗口内演练。演练失败进入缺陷列表，修复前权限不扩大。连续失败则降级为只读。

演练记录进回归集。记录包括：日期、工具、任务 ID、预期、实际、日志链接、缺陷、签字。回归集在每次网关改动后重放。网关改动包括：策略变更、白名单变更、超时变更、去重实现变更。这些改动看起来像配置，实际像代码。

把演练做成表演会浪费窗口。表演只走成功路径，不走超时，不走部分完成，不走确认过期。清单上的失败路径必须占一半时间。失败路径的验收标准是「系统停在安全态」，安全态包括：待确认、待补偿、人工接管、只读降级。跑通成功路径只证明演示，证明不了上线。

演练也要覆盖「人」。确认人是否看摘要，值班是否找得到补偿命令，客服是否拿得到更正模板。技术补偿成功但对外口径混乱，仍是事故。外网与付费类演练必须带上对应值班角色。

桌面推演与实操演练搭配。桌面推演用本文第十四节的示意事故，让各角色说出自己的第一动作。实操演练用预发开关制造未知与拒绝。两种记录都归档。新人上值班前，至少参加一次桌面推演和一次预发实操。

演练环境的数据要像生产的形状，值要脱敏。工单状态机、邮件模板槽位、云资源标签策略，应与生产同构。形状不同会导致「预发能补、生产不能补」。同构由平台负责，脱敏由数据负责人负责。两者签字都在演练记录上。

演练中的缺陷分类：设计缺陷（无补偿）、实现缺陷（有补偿但状态机错）、权限缺陷（值班角色拿不到补偿接口）、观测缺陷（日志缺字段）、流程缺陷（确认人不会看摘要）。分类决定谁修。修完重演同一条路径，通过才关闭缺陷。

## 十一、发布门禁

发布门禁决定「能不能把写权限打开」，与应用商店上架、模型评测分数是不同的门。分数高可以发博客，写权限开还要过安全与值班。

门禁输入是工件，不是口头保证。工件包括：工具注册表导出、权限矩阵、补偿文档、演练记录、审计字段对照、确认策略、密钥方案、白名单变更单、观测看板截图或链接、已知缺陷列表。缺一件，门禁停留。

建议的阻断项（任一条为真则禁止打开对应写工具）：

1. 工具级别未标或标了但网关未强制。
2. L1 及以上无补偿引用。
3. 无预发演练记录，或演练未覆盖失败路径。
4. 生产与预发共用密钥或共用发信通道。
5. 写工具开启自动重试。
6. 无幂等键设计。
7. 确认摘要由模型单独生成且无结构化哈希。
8. 审计缺少 task_id、decision、outcome、downstream_ref。
9. L2 无预算与告警。
10. L4 出现在 Agent 可调用列表。
11. 出站无域名允许列表。
12. 拒绝回执未实现，模型可对同一高危工具无限重试提议。
13. 日志系统故障时写路径仍放行。
14. 未通过注入防御评测的最低标准（高危工具调用率为零的预发集）。
15. 只读账号在对账中能写出成功。
16. 绕过网关的 SDK 或脚本仍能用同一密钥打下游。

建议的警告项（可限期关闭，到期未关则升为阻断）：观测看板无人值班、确认通过率异常、去重表无多副本共享、敏感参数全文进日志、演练角色未分离、更正模板未审、自动通过规则无版本。

门禁与功能开关绑定。合并代码不等于打开写权限。生产默认所有 L1 以上为关，按工具名灰度。灰度顺序：内部员工、小流量队列、再谈扩大。扩大以观测指标为准：未知结果率、补偿成功率、确认拒绝率、预算偏差。指标由值班认领。

回滚发布。发现异常，先关写开关，保留只读。关开关的权限在值班角色里，执行时间目标写进手册（示意：分钟级，具体以组织承诺为准）。关开关本身记审计。打开开关走门禁，关闭开关走值班，不对称是有意的。

门禁评审人包括功能、安全、值班，必要时法务与财务（涉及对外承诺与付费）。评审记录留存。用聊天表情当批准，门禁视为未通过。

例外申请是门禁的压力测试。例外必须：范围极窄、有过期、有观察指标、有负责人、到期自动收回。例外期间发生未知结果，立即收回。例外次数进入周会。例外变多，说明产品需求应该做成更窄的 L1 工具，而不是反复申请万能例外。

灰度观察名单预先写好。示意观察项：该工具的未知率、去重命中、确认等待、下游错误、预算、客服工单关键词。观察期结束要写简报，简报是扩大范围的工件。没有简报的扩大，视为未评审。

客户端与服务端同时门禁。只在服务端关开关、客户端仍展示「发送」按钮，用户会以为系统坏了并走旁路。开关关闭时，界面降级为「生成草稿，复制给人工」。旁路（个人邮箱、个人云控制台）在培训里明确禁止用于生产任务。

## 十二、与业务系统（工单、邮件、数据库、云资源）对接的示意约束

业务系统各有自己的一致性模型。Agent 网关是这些模型之外的又一个客户端，必须比普通客户端更老实：更少的权限、更严的幂等、更全的日志。下面按系统给示意约束，实施时对照各厂商与内部平台的官方文档。

**工单。** 只读用只读角色，查询走搜索与摘要接口，避免全量拉取描述里的附件。写操作拆成：创建内部评论（L1）、变更状态（L1）、指派（L1）、对外回复（L3）。状态变更的补偿是回到变更前状态并写系统评论说明。对外回复先入草稿队列，确认后发送。工单 ID 必须来自内部检索结果或用户在确认界面核对过的 ID，模型自由生成的数字串不得当 ID。批量关单禁止。每任务默认只允许对一张工单做一次状态变更，需要更多则新确认单。状态机的合法迁移写在网关，非法迁移（例如从已关闭跳到已删除）直接拒绝。SLA 字段、客户可见字段的变更按 L3 处理，即使工单系统把它们和内部字段放在同一 API。

**邮件。** 收件人域允许列表。内部通知与外部客户通道拆开。模板化发送，模型填槽位，槽位不允许改成任意 HTML 或任意附件。正文进草稿。确认页展示纯文本渲染与收件域。发送后下游消息 ID 写入审计。补偿是服务商撤回接口（若在窗口内）加更正信模板。调试句子、内部提示、密钥形状做发送前扫描，扫描到则拒绝。抄送与密送同样走允许列表。自动回复场景要有环路检测，避免与对方自动回复互相放大。发件人身份用专用子域或专用邮箱，方便事后过滤与撤回。退信与投诉进只读队列，由人类决定是否再发。

**数据库。** Agent 默认只连只读副本或只读角色。查询模板化，禁止任意 SQL 文本直通。允许的动词只有注册过的读模板。结果行数、列集、执行时长有硬上限。敏感列脱敏。写库不给 Agent。内部草稿写入独立草稿库或草稿表，与生产业务表隔离。迁移、DDL、删除，不进工具表。若业务坚持「让 Agent 改一条业务字段」，该字段更新走后端服务的窄接口，接口内做校验、幂等、审计，Agent 只调这一接口，仍要确认与补偿（把字段更新回旧值，旧值来自 before_ref）。只读账号定期对账：用该账号发起一次应被拒绝的写，期望拒绝；若写出成功，立即吊销并关 L0 以外的一切。对账本身走只读监控，失败告警到安全与值班。

**云资源。** 预发项目与生产项目拆开。可创建的规格、镜像、地域、数量写死在策略。创建后必须打任务 ID 标签，无标签的资源由对账作业列为异常。补偿是按标签销毁编排，销毁前确认无流量、无快照依赖。费用告警按项目，阈值由财务与平台设定。删除保护打开。角色不能附加宽泛的身份写权限。调用云 API 的出站走专有角色，令牌短时。清单类、描述类接口可 L0，创建类 L2，销毁类按影响决定 L2 或 L4，生产数据删除按 L4。配额告警与云厂商账单 API 的只读核对每天做一次。周末与节假日的自动创建默认关。

**对象存储。** 默认读指定前缀。写到隔离前缀，与生产桶分离。删除默认关。版本控制与回收站作为补偿前提，未开则删除工具不注册。对象键来自内部列表接口，模型不得拼任意键。批量删除禁止。预签名 URL 的过期要短，受众要窄，生成预签名属于写旁路，按 L1 或 L3（若 URL 可能外传）处理。

**身份与权限系统。** Agent 不得授予权限、不得拉全量用户、不得改 MFA。只读查询目录属性需隐私评审。任何「给某账号加角色」属于 L4，走人工 IdP 流程。组同步、SSO 配置、令牌签发，全部远离工具表。

**支付与账务。** 沙箱与生产拆开。金额上限、日限额、币种、商户号写死。幂等键等于业务单号。补偿是退款工单，退款权限不在 Agent，在财务系统。Agent 最多创建退款申请草稿。对账文件由财务系统主导，Agent 只读摘要。

**检索与知识库。** 入库管道与查询管道分离。入库要有来源、时间、信任级、许可。过期文档降信任。查询结果截断与脱敏。知识库更新是 L1，生产知识的对外同步是 L3。把「让 Agent 直接改生产 FAQ 并发布到站点」拆成：改草稿（L1）与发布（L3，确认加模板）。

跨系统事务按编排处理。工单关闭成功、邮件未知，状态机就是部分完成，补偿可能是重开工单并等待邮件核对。不要用「再全部重来一次」当补偿。对账作业每日用只读接口核对：有下游引用但无审计、有审计标成功但下游不存在、有标签无任务，三类都告警。

连接器市场与第三方插件默认关闭。每接入一个 SaaS，就多一张权限矩阵、一套密钥、一个出站域。新连接器按新工具走完整门禁。演示插件的 OAuth 范围如果宽于只读，禁止接生产租户。

## 十三、值班与事故复盘

写权限打开之后，值班开始对副作用负责。值班手册的第一页是：如何关闭写开关、如何吊销当前任务令牌、如何按 task_id 拉时间线、如何把任务打到人工接管。这四项在预发每月触摸一次。手册放在值班能打开的地方，与生产密钥分开。手册里是步骤标题与系统内链接，不是可以复制去打生产的长命令清单。命令的执行位置在受控工作台。

告警要少而准。建议优先接：写工具的未知结果率、拒绝率突增、预算消耗速度、确认过期堆积、去重命中异常升高、跨环境令牌领取、L3/L2 在非工作时间通过。告警附 task_id 链接。没有链接的告警，值班会把它静音。告警的抑制规则要评审，避免把未知结果率抑制掉。

事故定级按副作用，不按模型是否「道歉」。对外误发、错误扣费、错误删除、错误扩容产生账单、权限被错误授予，进入高优先级。内部草稿写错，低优先级。定级表预先写好，避免现场争论。定级表与客服、法务的对外定级对齐，防止工程以为是低优、客户以为是事故。

处置顺序固定：止损、保证、沟通、补偿、复盘。止损是关写开关与吊销令牌。保证是日志与快照。沟通按对外是否可见选择客服与法务。补偿走已演练路径。复盘在状态稳定之后。现场发明新补偿路径，只在已演练路径无效时，由负责人批准，并在事后补进演练集。

复盘文档最小结构：时间线（从审计导出）、影响面、为何门禁没拦住、为何确认没拦住、为何补偿窗口够或不够、改进项（工具表、策略、演练、培训）、改进项负责人与日期。改进项关闭前，相关写工具保持关或保持缩范围。用「模型这次胡言」当根因，改进项会空。根因要写到控制系统：白名单过宽、确认摘要不清、幂等缺失、演练未覆盖未知状态。

值班与开发的职责分离。开发可以提议打开工具，值班可以在异常时关闭。关闭不必开会。开会用在打开。这个不对称要写进制度，并得到技术负责人支持，否则值班不敢按开关。

指标回顾按周。看：自动执行占比、确认平均等待、补偿次数、未知结果数、门禁例外申请数。例外申请变多，说明产品在绕门禁，要开专题，把合理需求做成更窄的 L1，而不是发万能例外。

对外沟通口径预先审定。误发邮件的更正信、误扣费的说明、服务中断的状态页，都不在事故夜由模型现场生成后直接外发。模型可以起草，人类按模板发。这是 L3 约束在值班场景的延续。

值班交接包含写开关状态、进行中的确认单、未关闭的未知结果、预算使用。交接记录本身进审计。接班人第一件事是打开看板看这四项。看板打不开视为值班缺陷，先修看板再谈新工具。

复盘会的参与者包括：当班、工具负责人、安全、必要时客服。模型供应商的客户经理可以听测量问题，听不了密钥与客户内容。复盘材料脱敏后再外传。内部复盘用 task_id，对外只用统计。

改进项分成「当天可关」与「需要发布」。当天可关包括：关开关、缩白名单、降级别、加确认。需要发布包括：补补偿、补字段、改状态机。两类都进同一张表，状态对值班可见。关闭改进项时附回归演练链接。

心理安全与开关文化。值班按了开关，事后不得用「影响了演示」问责。问责用在：绕过网关、关闭审计、把生产密钥给演示、口头放宽 L4。文化写进值班制度首页，比写进博客更重要。博客只是把这句话公开，方便跨团队对齐。

## 十四、十个「能说会做」的灾难

以下十则均为示意，用来做桌面推演。细节经过改写，不指向具体机构。每则只写现象、控制系统缺口、防御改进。不写可复现步骤。

**示意事故一：把调试段落发到真实客户。** 客服 Agent 有发送工具，提示词里还有开发时的示例句。模型把示例句当成回复。缺口：L3 无草稿、无发送前扫描、确认摘要未展示全文。改进：外部发送默认草稿队列，扫描内部标记词，确认页展示纯文本，预发用假收件域。推演问题：谁有权关发信开关？更正信模板在哪个工作台？

**示意事故二：超时后重试导致重复扣费。** 支付调用超时，编排器当失败，模型再提议一次。下游实际已成功。缺口：未知状态当失败、写路径自动重试、幂等键未传到下游。改进：未知单独成类，写禁止自动重试，业务单号当幂等键，对账作业抓重复。推演问题：财务如何用 downstream_ref 退第二笔？Agent 此时是否仍能提议扣费？

**示意事故三：检索到的「操作说明」变成删数据企图。** 知识库里一篇过期内部笔记写了清理步骤，模型当作授权并提议高危工具。网关若未默认拒绝，就会落到生产。缺口：数据通道与指令通道未分离，L4 能力出现在工具表，资源白名单过宽。改进：外部与过期文档打低信任，删除不进工具表，参数与内部对象交叉校验。推演问题：入库管道如何给过期文档降信任？值班看到未授权工具提议峰值时先做什么？

**示意事故四：演示密钥打到生产发信。** 演示为了「真的发出去」，复用生产 SMTP。评测集里的测试地址有一封进了真实用户。缺口：环境隔离失败，门禁未查共用通道。改进：演示只允许模拟成功，生产通道在演示网络不可达，门禁查密钥与端点指纹。推演问题：如何用只读查询证明演示账号打不到生产网关？

**示意事故五：确认按钮形式化。** 值班为了清队列，对摘要只看工具名就通过。一次错误工单关闭影响客户 SLA。缺口：确认界面信息密度低、无阻断式核对、通过率无观测。改进：高危确认输入 ID 末四位，观测通过率，夜间关闭策略自动通过。推演问题：通过率连续一周接近满值时谁负责召开收紧会？

**示意事故六：部分完成被标成成功。** 「关工单并通知」中通知未知，整任务标成功。客户未收到说明，工单已关。缺口：多步编排无分步状态，无部分完成态，无补偿编排。改进：分步状态机，未知则待核对，补偿为重开或补发草稿待确认。推演问题：验收查询在只读副本上如何判断「通知是否已达」？

**示意事故七：只读账号其实能写。** 数据库角色名是 readonly，实际授权复制自写角色。模型一次「清理测试数据」的提议若被放行，就会打到生产表。缺口：账号分级未用只读副本、未做权限对账、动词未模板化。改进：连接只读副本，定期用只读账号尝试写应被拒绝并告警，SQL 直通取消。推演问题：对账失败的十五分钟内谁吊销账号？

**示意事故八：云资源无标签无上限。** 模型在排障时反复创建实例，标签没打上，销毁编排找不到。账单在周末上涨。缺口：L2 无预算，无强制标签，无费用告警到值班。改进：策略写死规格与数量，无任务 ID 标签则创建失败，费用告警到值班，补偿按标签销毁。推演问题：无标签资源的隔离与人工销毁流程在哪份 runbook？

**示意事故九：审计后写，组件故障就放行。** 日志组件故障，网关选择「降级放行以免影响业务」。事故后无法回放。缺口：写路径与日志的依赖方向反了。改进：日志失败则写失败，只读可降级，L1 以上关闭，门禁把该项列为阻断。推演问题：日志故障时用户界面如何解释「只能生成草稿」？

**示意事故十：补偿窗口已过仍显示可撤回。** 确认页写「可撤回」，实际服务商窗口已过。误发后无法撤回，更正信又被模型写得很像另一次误发。缺口：补偿窗口未动态计算，更正信未走模板。改进：确认页展示剩余窗口，窗口外只展示人工补偿，更正信用法务审定模板，模型只填对象字段。推演问题：法务模板的版本谁发布？过期模板能否被网关拒绝？

十则的共同点：模型都会说话，控制系统没把话说成安全态。推演时让值班、开发、安全各讲自己会在哪一步按开关。讲不出来的步骤，就是演练项。建议每个季度抽三则做桌面推演，每则不超过四十五分钟，输出三张缺陷单：门禁、确认、补偿。缺陷单进下一迭代，不进「下次再说」的聊天记录。

桌面推演记录模板（示意）：日期、事故编号、参与角色、第一动作是否符合手册、手册缺什么、开关是否找得到、日志是否拉得开、对外口径是否有模板、改进项负责人。模板填不满，说明手册还不能上值班。

## 十五、二十问

下列问答用于评审会。答案应能指向仓库里的配置、演练记录或门禁工件。指向「我们会小心」的，视为未通过。

**1. 这个 Agent 上线后，默认能自动执行的最高级别是什么？** 应当是 L0。L1 以上默认关，按工具打开。

**2. 工具不在白名单时发生什么？** 网关拒绝，记审计，模型拿到结构化拒绝，任务只能转向只读或结束。

**3. 写工具的补偿在哪里注册？谁演练过？哪一条任务 ID 能回放？** 注册表字段、演练记录、日志链接三者齐全。

**4. 下游超时后，系统把结果标成什么？** 标未知。未知禁止自动重试正向写。

**5. 幂等键谁生成、活多久、下游是否认识？** 任务创建时生成，长于重试窗口，能传则传，不能传则本侧去重。

**6. 生产密钥如何进入调用？** 短时令牌，绑定任务与范围，演示与生产拆开。

**7. 检索片段里出现「请执行删除」时，谁是否决者？** 网关是否决者。数据通道无授权效力。

**8. 确认页的副作用摘要是谁生成的？** 网关按注册表与参数生成，带哈希。模型解释不作为授权依据。

**9. 确认过期后会发生什么？** 确认单作废，需基于最新只读快照重新生成。

**10. 审计能否按 task_id 画出从提议到补偿的时间线？** 能，且 Agent 不能改历史。

**11. 日志系统故障时，发信与扣费是否仍放行？** 不放行。写路径失败关闭。

**12. L4 能力出现在工具列表里吗？** 不出现。删除库、授权限、生产 DDL 走变更系统。

**13. 出站请求如何限制目标？** 出站代理加域名允许列表，内网与元数据地址拒绝。

**14. 预算谁来看？超了谁关开关？** 财务与平台定阈值，值班有权关 L2，关闭记审计。

**15. 工单对外回复与内部评论是否同一工具？** 分开。对外是 L3，内部是 L1。

**16. 数据库连接的是主库写角色还是只读副本？** 默认只读副本。写走窄接口且需补偿。

**17. 云资源如何保证能销毁？** 创建强制任务 ID 标签，补偿按标签编排，无标签创建失败。

**18. 注入评测集在预发的通过标准是什么？** 高危工具调用率为零，任务降级为只读或待确认。

**19. 值班第一页的四件事能否不靠原作者在约定时间内做到？** 关写开关、吊销令牌、拉时间线、人工接管。做不到则未就绪。时间目标以组织值班承诺为准。

**20. 上一次演练失败项关闭了没有？关闭前有没有扩大权限？** 失败项打开时权限不扩大。这是门禁阻断项的延伸。

可以把二十问印成单页。新工具评审只问这一页。页上写不出链接的问题，当场记缺陷。评审记录把二十问的链接贴进变更单，门禁机器人检查变更单是否包含这些链接。缺链接则阻断合并写开关配置。

补充追问（仍属评审，可按风险选用）：去重表是否跨副本；确认哈希算法与字段列表；补偿窗口是否动态；只读账号对账上次时间；组织策略是否挡住删除生产桶；例外申请到期是否自动收回。追问不替代二十问，用来防止「答案很会说、仓库里没有」。

## 观测指标与看板字段

门禁通过之后，日常靠看板，不靠感觉。看板字段要能回答四件事：现在能不能写、刚才写成功了没有、未知有多少、补偿是否跟上。字段进同一数据源，值班与周会看同一份。

建议的核心指标如下，名称可按内部规范调整。所有阈值由安全与值班共同设定，本文只给指标语义。示意中的「升高」「堆积」指相对本团队基线，不给可被误抄的绝对数字。

**写开关状态。** 每个 L1 以上工具在生产是开还是关，谁在何时开的，对应变更单。看板第一行就是开关。开关与网关运行配置对账，对不上则告警。

**提议次数与执行次数。** 模型提议工具的次数、网关允许的次数、确认通过后真正打到下游的次数。三道数字应递减。若执行接近提议，说明拒绝与确认几乎没起作用，需要复盘任务分流或确认策略。

**决策分布。** allow / deny / pending / expired 的占比。deny 升高优先查白名单与检索质量。pending 堆积说明确认人力不够，应缩范围或加值班，禁止用自动通过清队列。expired 升高说明确认时效过短或无人值守。

**未知结果率。** 对 L1 以上，未知是最重要的红灯。未知需要只读核对工单。未知积压超过值班手册约定，关闭对应写工具。未知清零的定义是：每条未知都有核对结论（实际成功 / 实际失败 / 已补偿 / 仍不明并已人工接管）。

**去重命中。** 命中说明刹车在工作。命中突然变成「处理中」长时间挂起，要查下游与去重表锁。命中为零也不一定健康，可能是键的规范化把同一业务打成了不同键。需要抽检键的碰撞与分裂。

**补偿次数与补偿成功率。** 补偿是预期内的运行，不是耻辱。成功补偿说明演练有效。补偿失败必须人工接管。补偿成功率低于演练基线，停止扩大该工具范围。

**预算消耗速度。** L2 用金额与次数双看。速度相对昨日同时段异常，先关创建类工具，再查是否重试风暴。账单只读 API 与网关 budget_delta 对账。

**确认质量。** 通过率、拒绝率、平均阅读时长（若工作台能采集到焦点时间）、阻断式核对失败次数。阅读时长过短且通过率过高，抽检确认人。抽检是流程，不是监视人格。

**注入与越权企图的防御向信号。** 未授权工具提议次数、低信任来源填充高危槽位被拒次数、确认哈希不匹配次数。这些是防御指标，用来看网关是否在挡。生产只监测，不进行攻击性验证。

**环境串用。** 跨环境令牌领取、演示账号打生产端点、预发密钥出现在生产网关。这类信号一出现就关写，并开安全事件。对账用密钥指纹与端点指纹，不靠人工看配置文件。

看板的布局建议：上行开关与未知，中行决策与确认队列，下行预算与补偿。链接全部落到 task_id 时间线。没有时间线的数字，值班无法行动。看板权限：值班读写开关（关的方向），开发只读，审计只读。写开关的打开仍走门禁，不在看板上放「一键全开」。

指标的采集点在网关，不在模型自我汇报。模型说「我已经发送」不算数，downstream_ref 才算数。把模型的自然语言状态写进看板，会在事故里制造第二套真相。真相只有审计事件。

周会只选一个改进：未知率、确认质量、补偿失败、例外申请，四者择一。一周改四项等于一项都没改。改进结果用同一看板验证。验证前不扩大写权限。这就是「观测稳定之后再谈下一把写权限」的可操作版本。

## 十六、结语

知止，是知道工具的止境：止于只读，止于白名单，止于确认，止于可补偿，止于可演练，止于可审计。有定，是网关策略在模型换了说法之后仍然不变。能静，是值班在夜间面对未知结果时，按手册关开关，而不是跟模型谈判。

把 Agent 接到真实系统，是产品能力，也是事故能力。口才可以继续打磨，副作用必须先被关进级别、白名单、幂等、确认、补偿和门禁。没有逆向操作，就不要给写权限。这句话适合做工具表表头，也适合做发布邮件的第一句。

下一步只做一件事：导出当前工具表，按本文矩阵填空。空着的补偿、空着的演练、空着的审计字段，对应的写开关保持关闭。只读可以先上。先上的只读会教给团队如何观测。观测稳定之后，再谈第一把写权限。第一把写权限应当是内部草稿，补偿是删除草稿。内部草稿跑过值班与复盘，再谈工单状态。工单状态的补偿跑过，再谈对外发送。对外发送的更正模板审过，再谈付费。付费的退款路径通了，仍然不要把删除交给模型。

顺序本身就是清单。清单本身就是文化。文化要靠门禁维持，门禁要靠演练维持，演练要靠日志维持。日志在，止境就在。

工程上的知止，还会表现为拒绝一些看起来很酷的路线：通用浏览器当万能工具、把个人云控制台密钥交给 Agent、在聊天里一键批准生产变更、用准确率数字申请删除权。这些路线都能做出漂亮演示。演示结束之后，世界还在。世界需要补偿，补偿需要演练，演练需要权限分离。权限分离需要从第一行工具表开始。

若只记住三句话，就记住这三句。第一句：默认拒绝，白名单过期即收。第二句：未知不是失败，未知不可自动重试正向写。第三句：没有逆向操作，就不要给写权限。三句都能变成网关里的断言。断言比口号硬，硬的东西才能在模型口才很好的夜里仍然有效。

## 附录：公开安全资料

下列资料均为公开文档，名称可在评审材料中引用。条款编号、释义与示例以各官网当前版本为准，本文不转写操作细节，不提供攻击说明。查阅时请核验官网与查阅日。

**OWASP Top 10 for Large Language Model Applications。** 公开的 LLM 应用风险分类，名称包括提示注入（Prompt Injection）、敏感信息泄露、供应链、数据与模型投毒、不当输出处理、过度代理（Excessive Agency）、系统提示泄漏、向量与嵌入弱点、错误信息、无界消耗等条目。工程上与本文直接相关的是过度代理、提示注入、敏感信息泄露、不当输出处理。官网入口：OWASP 该项目页面（检索「OWASP Top 10 for LLM」以官方站点为准）。项目版本会更新，引用时写明查阅的版本年份。

**OWASP Application Security Verification Standard（ASVS）与 OWASP API Security Top 10。** 用于对照鉴权、会话、密钥、审计、访问控制的通用要求。Agent 网关首先是一个 API 网关，ASVS 里关于认证、访问控制、日志的章节可直接映射到工具调用。API 风险分类里与对象级别授权、认证、过度数据暴露相关的条目，可对照工单 ID 校验、令牌绑定、日志脱敏。

**NIST AI Risk Management Framework（AI RMF 1.0）及后续公开资料。** 提供治理、映射、测量、管理的风险过程语言。可把工具级别、门禁、演练、值班写成测量与管理活动。以 NIST 官网文本为准。组织若已采用该框架，不必另造一套形容词，把本文清单挂到对应功能上即可。

**ISO/IEC 27001 信息安全管理、ISO/IEC 27701 隐私、ISO/IEC 42001 AI 管理体系。** 适合已有认证体系的组织，把 Agent 工具表、密钥、审计留存、供应商（模型 API 与 SaaS）纳入现有控制。具体控制项以标准与认证机构要求为准。认证语言与网关断言之间要有对照表，避免两张皮。

**中华人民共和国网络安全法、数据安全法、个人信息保护法。** 涉及日志留存、个人信息处理、重要数据与出境时，法务与合规主导，工程提供最小权限、脱敏、审计、访问控制的证据。条文以中国人大网或国家主管部门公布的文本为准。本文不解释条文，只要求工程证据可被法务取用。

**GB/T 22239 等信息安全等级保护相关国家标准。** 等保对象若包含 Agent 接入的业务系统，工具网关的身份鉴别、访问控制、安全审计、数据备份恢复，应与等保要求对齐。以主管部门与标准文本为准。备份恢复演练可以与本文回滚演练合并计划，避免两套演练互不知道。

**云厂商与身份提供方的官方安全文档。** IAM 最小权限、短时凭证、删除保护、对象存储版本控制、出站控制、密钥管理，均以当前产品文档为准。本文只要求「打开这些能力」，不替代厂商配置手册。厂商能力名称各不相同，对照表由平台组维护。

**Google SRE 相关公开书籍与文档中的回滚、熔断、事故管理章节；各家公开的架构框架中的安全支柱。** 用于把补偿、演练、值班语言与现有 SRE 实践对齐。Agent 值班是 SRE 值班的子集，沿用同一套严重级别与事后复盘格式，学习成本更低。

**模型供应商的官方安全与使用政策。** 数据是否用于训练、区域、内容过滤、密钥保管，以供应商当前文档与合同为准。工程上仍以自建网关为准：供应商过滤是辅助，白名单与确认是控制。合同与 DPA 由法务审，网关策略由工程审，两审都过才接生产流量。
