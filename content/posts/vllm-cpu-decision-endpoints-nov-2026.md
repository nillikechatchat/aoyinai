## 一、门槛重估：没有显卡，也能起推理服务

「先装 CUDA，再谈大模型」曾是入门第一课。2026 年 11 月这条前提松动了：vLLM v0.33.0 起官方提供 x86_64、arm64 与 macOS 的 CPU wheel 和 CPU Docker 镜像（来源：vLLM 官方 GitHub Releases，2026-11 前后发布），SGLang v0.5.22 也宣布支持 Apple Silicon（来源：SGLang 官方 Releases，2026-10-19）。一台普通笔记本、一台无卡云主机，就能把开源模型起成 OpenAI 兼容服务。本文把这条零显卡路径走通，再讲 10-11 月推理引擎新增的「决策端点」——它让大模型在分类、打分这类任务上，比生成式调用更省、更快。所有版本号、参数名以官方文档与 Releases 页面为准，下文不再逐处重复。

![工欲善其事，必先利其器](/images/illu-tutorials.png)

《论语》说「工欲善其事，必先利其器」。利器的前提是知道自己要做什么活：起服务、做分类、跑 MoE，对应三条不同的路。CPU 适合验证与服务小模型；决策端点适合高并发分类；Paged Experts 适合只有一张消费级显卡却想跑大 MoE 的场景。三条路可以串成一条成长线：先在 CPU 上把流程跑通，再按预算逐级加算力。

### 1. CPU 模式适合什么、不适合什么

CPU 推理的真实边界要提前说清。适合的：7B 以下小模型、量化模型、批处理离线任务、决策类短输出调用；以及团队没有 GPU 预算时的接口验证与联调。不适合的：长上下文生成、低延迟在线对话、大参数稠密模型的实时服务。示意：假设同一台 8 核云主机，跑 1.7B 级小模型做短输出分类，吞吐能满足百人内部工具；换成 70B 模型生成千字回答，等待时间会以分钟计。数字是示意，实际以自测为准。

安装路径现在很直接：pip 安装 vLLM 后，官方 wheel 在 CPU 环境可直接工作，无需再手工编译（v0.33.0 起，macOS 也有 wheel）。容器路线用官方 CPU Docker 镜像，适合与现有部署流程对接。

```bash
# 安装（以官方文档为准，版本随时间演进）
pip install vllm

# CPU 上起一个 OpenAI 兼容服务（示意命令）
vllm serve <model-id> --dtype float32
```

启动后，`/v1/chat/completions` 与标准 OpenAI SDK 完全兼容。把 `base_url` 指向本地端口，客户端代码零改动。这一步的价值在于把「环境问题」和「模型问题」分开：先证明链路通，再谈效果差。

### 2. 把大模型当分类器用：决策端点

11 月推理引擎有一个被低估的更新：结构化决策端点。vLLM v0.32.0 新增 `POST /v1/systemone` 结构化决策端点（choice/score 类问题，默认开启），v0.33.0 延续并标准化了 `/v1/decisions`；SGLang v0.5.21 同期上线 Decisions API 与 Score API（来源：两家官方 Releases，2026-10 至 11 月）。这些端点把「判断题」从生成式调用里拆出来：输入一个问题与候选选项，输出结构化决策，而非自由文本。

为什么值得单独一个端点？分类任务走生成式接口，输出要解析、要防格式漂移、要为多余 token 付费；决策端点在协议层约束输出结构，配合专门的决策类小模型（如 Hugging Face 上新出现的 DiffusionGemma 决策模型系列，社区已有「CPU 上跑低成本决策模型」的实践文章，2026-11），延迟与成本都下降一个量级。示意对比：假设舆情场景每天 50 万条「是否负面」判断，生成式调用按百 token 计费；决策端点按一次决策计，成本差距可达数量级——具体倍数取决于模型与厂商定价，以官方计费页为准。

落地姿势是给系统分层：意图识别、情感判断、合规初筛这类「选项有限」的任务走决策端点；需要组织语言的任务走生成式。一层协议改动，账单结构立刻不同。

### 3. 单卡跑大 MoE：SGLang Paged Experts

如果预算只够一张消费级显卡，SGLang v0.5.23（2026-11-02 发布）的 Paged Experts 是本月最值得关注的特性：opt-in 开启后，专家权重分页驻留，单卡可以运行总参数超过显存容量的 MoE 模型，官方给出的对比数据是相对 CPU offload 最高 30 倍加速；量化 MoE（FP8/NVFP4）上还能挂 LoRA（来源：SGLang 官方 Releases v0.5.23）。

它的工程含义是「显存容量」从硬门槛变成软约束。前提要记三条：这是 opt-in 特性，需显式开启；收益取决于专家命中率，任务越集中收益越稳；30 倍是官方对比数据的上限，自己的任务自己测。

### 4. 零显卡起步的三步路线

把上文收拢成可执行的路线：

| 阶段 | 目标 | 工具组合 | 参考成本 |
| --- | --- | --- | --- |
| 第一步：链路通 | 本机起服务、调通 SDK | vLLM CPU wheel + 1.7B 级小模型 | 0 元（自有电脑） |
| 第二步：任务分层 | 分类走决策端点、生成走对话端点 | /v1/decisions + 决策类小模型 | 低（短输出） |
| 第三步：按需升档 | 单卡跑 MoE 或租卡 | SGLang Paged Experts / 按需 GPU | 按小时计 |

每一步都有明确的「完成判据」：第一步是本地 curl 通；第二步是同一批样本上决策端点的延迟与成本低于生成式（自测数据，示意即可）；第三步是目标 MoE 在单卡上出首个有效 token。判据清晰，升级决策就不会靠感觉。

### 5. 写在最后

《荀子·劝学》讲「假舆马者，非利足也，而致千里」。CPU wheel、决策端点、Paged Experts 都是「假物」：借协议与系统的力，补算力的短。入门者的顺序应该是先在零成本环境把工程链路跑通，把任务分层，再决定把钱花在哪张卡上。本文所有版本号、端点名与性能数据截至 2026-11-10 核验，均以 vLLM、SGLang 官方文档与 Releases 页面最新公告为准。
