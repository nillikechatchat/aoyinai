## 一、为什么模型清单在面试里贬值

秋招季一到，简历上最常见的一行是模型名串成的清单：大模型、扩散模型、多模态、智能体，再加一串公开权重的名字。清单本身没有罪，它只是目录。问题出在目录被当成了能力证明。面试官打开仓库、追问评测、要你把一次失败讲清楚时，清单立刻变成空气。

《大学》讲「知止而后有定，定而后能静」。止，就是先分清什么叫证据、什么叫标签。标签可以一夜之间写进简历；证据必须经过问题、方法、结果、复现、反思五段，才能在追问里站得住。

模型清单贬值，有三条公开可观察的原因。

第一，公开模型与教程把「能跑通官方示例」的门槛压得很低。能调用一次聊天接口、能微调一份教学数据集、能在笔记本里画出损失曲线，已经是大量课程与公开材料覆盖过的动作。面试官默认你会这些，默认值不构成区分。

第二，招聘侧要的是可移交的工作。组里真正怕的是：人来了以后，评测集在谁手里说不清、一次线上回滚没有日志、一次数据泄漏没有责任边界。这些能力写不进模型名，只能写进你做过的约束、记录与复盘。

第三，模型名更新很快。把易变的名字当主证据，等于把简历的保质期绑在厂商发布节奏上。名字会过期，问题定义、评测协议、失败分析和工程约束更耐放。

本文把升学、选实验室、课程、大作业、科研、实习、开源、比赛、简历、面试、转正写成同一条链。写作原则与本站《大模型应用开发实战手册》一致：凡结论，落到可核验的方法或公开资料上；凡涉及招生分数、录取名额、排名、薪资、转正比例、内推结果，一律不编造，提示以学校研究生院、招生办和用人单位招聘官网的最新公告为准。文中数字与经历凡未标注出处的，均为示意或假设。

下面这张表把清单叙事和证据叙事放在同一组问题上，方便你对照自己的材料。

| 面试官常问的事 | 清单叙事的典型答法 | 证据叙事的典型答法 |
| --- | --- | --- |
| 你做过什么模型 | 报一串模型名与参数规模 | 说明任务、数据范围、指标、失败样本 |
| 效果好不好 | 效果很好、接近公开榜单第一档 | 给出评测协议、对照实验、误差分析 |
| 你的贡献是什么 | 参与了训练 | 切分到可核验动作：数据、评测、脚本、文档、值班 |
| 别人如何复现 | 代码在仓库里 | README、随机种子、依赖锁定、一条命令、已知失败 |
| 出了问题怎么办 | 再调一调 | 回滚路径、日志字段、责任人、复盘记录 |
| 安全与合规 | 我们有过滤 | 输入输出审核、日志留存、标识义务、权限隔离 |

读这张表时请记住：证据链服务的是核验，核验服务的是信任。信任一旦建立，模型名只是附录。

面试官贬值模型清单，还有一层组织原因。校招与实习招聘要在有限时间内完成核验。核验成本最低的路径是：打开你提供的链接，按 README 跑最小命令，看评测表是否自洽，听你把一次失败讲到可操作的下一步。清单无法进入这条路径。你报出的模型名越多，追问越会集中到「你究竟独立做完过哪一段」。准备秋招的同学，应当把材料从「我会哪些模型」改写成「我闭环过哪些任务」。

一份只含模型名的简历，在筛选阶段也许能通过关键词。进入面试后，关键词变成负债：每一项都可能被要求当场讲清数据、指标、贡献与失败。写不进五段链的名字，删掉比留下更安全。留下的每一项，都要能在五分钟内被核验。

假设一位同学（经历为示意）在简历技能栏写了六种模型家族。面试官只追问其中一项检索问答。同学讲不清切分方式、说不清幻觉如何定义、拿不出失败样本。六项技能在这一问之后同时失信。另一位同学只写一项：课程文档问答，附评测协议与仓库链接。面试四十分钟都围绕这一项展开，信任反而上升。区分来自可核验性，来自你愿意把范围变窄、把证据变厚。

秋招材料的第一原则因此非常具体：简历上的每一个项目，都必须能指向一个可运行、可评测、可复盘的对象。对象可以很小。小而闭合，大于大而空洞。

## 二、证据链是什么：问题、方法、结果、复现、反思

一条证据链最少有五段。缺任何一段，面试里的追问就会在缺口处断裂。五段可以压进一页纸，也可以铺成仓库。长度不重要，闭合重要。

**问题。** 你要解决的是谁的什么任务，成功标准是什么，失败代价是什么。问题要写成可观察的句子。例如（假设）：客服工单需要在三十秒内给出类别与理由，类别集合固定为五类，未知时必须输出 unknown，错误分类会把退款单打进物流队列。这句话里有对象、时限、标签空间、拒答出口和业务代价。空洞的「做一个智能客服」还停留在方向词，进入不了评测。

写问题有一个实用检查：把这句话交给没做过这个项目的同学，请对方根据这句话列出五条测试用例。若对方列不出，说明问题还不够可观察。测试用例会倒逼你补上输入边界、拒答条件和失败代价。问题一旦可测，后面的方法才有对比对象。

**方法。** 你选了什么路线，为什么选它，放弃了什么。方法包括模型，也包括数据切分、检索、规则、人工审核、超时与降级。把方法写成决策记录：先基线，再加模块，每次只改一个变量。决策记录的价值在于，面试官可以顺着变量问「如果当时选择另一条路会怎样」，你也能答到实验而不是情绪。

方法段最常见的空洞是把工具清单当成方法。调用某家接口、使用某个框架、堆上某个向量库，这些是实现细节。方法要回答的是：基线是什么、你增加的约束是什么、你如何处理资料不足、你如何防止测试泄漏。实现细节可以放进附录或仓库，主叙述保持决策。

**结果。** 结果必须绑定评测协议。协议写清数据集版本、划分方式、指标定义、抽样方法、人工抽检比例。没有协议的数字，只是气氛。涉及公开榜单分数时，写明榜单名称、提交日期，并提示读者以榜单官网当前页面为准；本文不转述具体分数。

结果段还要准备失败样本。成功样本证明系统在舒适区能工作；失败样本证明你见过边界。面试深挖时，失败样本比平均值更有信息量。你应当能随手抽出三类失败：检索错误、生成未使用资料、资料本身过期或冲突。三类失败对应不同的修复动作，能分开讲，就说明你做过归因。

**复现。** 别人，包括三个月后的你，能否按文档把关键实验再跑一遍。复现物包括：代码提交哈希、数据获取说明、环境锁定、随机种子、硬件约束、已知失败。复现是让下一步的人少问「这是哪一版」。课程作业里把笔记本导出成网页，只解决了阅读，没有解决复现。

最小复现路径建议写成一条命令加一份已知问题列表。命令负责「能跑」；已知问题负责「跑完以后哪些地方仍然会错」。两者齐全，才叫复现材料，而不是演示材料。

**反思。** 反思写清边界：在什么数据上失效、对什么攻击面脆弱、下一步不做什么。反思的价值在于证明你能止损。知止，就是承认范围。把反思写成感想，例如「我学到了很多」，核验者无法使用。把反思写成「口语化改写导致召回下降，下一步做查询改写，暂缓多模型路由」，核验者可以追问你的判断依据。

下面用一张表把每段的最小交付物钉死。

| 证据段 | 最小交付物 | 常见空洞 | 核验方式 |
| --- | --- | --- | --- |
| 问题 | 一句话任务定义，加上成功与失败标准 | 只有方向词，没有用户与代价 | 让同学按这句话写出测试用例 |
| 方法 | 基线、变量、放弃项 | 只列模型名与框架名 | 对照实验表能否独立阅读 |
| 结果 | 指标、协议、失败样本 | 只有「准确率很高」 | 能否指出指标定义与划分方式 |
| 复现 | README、依赖、种子、哈希 | 宣称无法复现又无替代说明 | 按文档能否跑通最小路径 |
| 反思 | 失效边界与下一步不做清单 | 把反思写成心情 | 下一次实验是否真的避开了旧坑 |

假设一位同学做课程问答机器人，五段可以长这样，全部为示意，并非真实项目。

问题：课程群里重复询问截止日期与作业格式，助教每晚重复粘贴同一段说明；目标是对截止日期、提交格式、评分构成三类问题给出可引用答案，其他问题明确拒答并转人工。

方法：先做关键词规则基线，再上文档切分加检索，最后才调用生成模型；生成时强制引用块编号，资料不足则输出「未在课程文档中找到」。

结果：用五十条真实提问的脱敏样本做评测，规模为假设；报告类别准确率、拒答率、幻觉率；幻觉定义为答案中出现文档未出现的日期或分数。

复现：公开评测集的构造说明、切分脚本、配置文件、一次失败的检索日志。

反思：对口语化改写提问召回下降；下一步做查询改写，暂缓上多模型路由。

这条链里，模型出现在方法段的后半，前面是问题与基线。面试官顺着这条链问，你每一步都有东西可指。证据链还有一个容易被忽略的性质：它是时间上的对象。今天的结果，要能接到明天的复盘；今天的复现物，要能接到交接。所以证据链同时服务三个人：招生或招聘的核验者、未来的同事、三个月后的自己。

子夏说「博学而笃志，切问而近思」。切问，就是把大词问成可测的小问题；近思，就是从自己仓库里的一次失败开始想，从自己能核验的那一段开始写。

证据链也可以按岗位说明书反向生成。打开目标岗位的官方招聘启事，把每一条技能要求改写成一个可观察问题，再看自己现有材料能否回答。答得上的，留下并补齐五段；答不上的，要么补一个小而闭合的项目，要么从简历删除以免被追问。岗位要求、工作地点、薪酬区间以用人单位招聘官网当前页面为准，本文不转述。

## 三、选实验室：三个信号、四个坑

实验室是证据链的上游环境。环境决定你能积累什么样的证据：有的组逼你把评测写成习惯，有的组只逼你把会议名写进年度总结。选组时，把注意力放在可观察信号上。本文不评价、不点名任何具体导师或院校排名，只给核验方法。具体招生政策、名额、分数线，以目标院校研究生院与招生办公告为准。

### 三个信号

信号一，方向匹配可核验。打开实验室近两三年的公开论文、开源代码、主页项目列表，看主题是否覆盖你想训练的能力。匹配的最小标准是：你能指出两篇公开工作，说明自己读懂了问题定义与评测，并写出自己能接手的一块。匹配看的是任务家族，例如序列建模、视觉识别、系统与编译、人机交互、安全与治理。把「都是人工智能」当成匹配，等于还没有开始核验。

方向匹配还要看时间。实验室主页上十年前的高引工作，说明历史贡献；近两年的公开仓库与预印本，说明你入学后更可能接到的任务。两者都值得尊敬，对你个人证据链更直接的是后者。若近两年公开材料稀少，你需要更多一问：组里工作是否因保密而无法公开。保密本身可以理解，你仍要问清学生个人能否在不泄密前提下积累可对外讲述的方法证据。

信号二，训练风格可见。训练风格写在学生的公开材料里：仓库是否有可运行说明，论文是否讲清基线与消融，组会讨论（若学长学姐愿意分享）是否包含失败。你可以问三个不冒犯的问题：新同学第一个月通常做什么；一篇工作从想法到可复现实验大概怎样分工；评测集由谁维护。能回答到动作层面的组，训练风格是可见的。只能回答到「我们很拼」的组，你看见的是气氛，还没有看见风格。

训练风格还有一个旁证：学生能否在二十分钟内讲清自己仓库里的评测协议。能讲清，说明组里把评测当公共语言；讲不清，说明产出可能高度依赖个人记忆。个人记忆无法交接，也无法在你毕业后继续为你背书。

信号三，导师时间可预期。时间的形式可以是双周组会、指定合作导师、高年级带低年级、异步书面反馈。关键是你能否预期下一次得到反馈的时间窗口。独立与放养的差别在于：独立有检查点，放养只有截止日期。问「我如何知道自己这周有没有走偏」，比问「老师厉不严厉」更接近事实。

导师时间还包括回复的形态。有的反馈是具体到实验设计的书面意见，有的反馈是方向性的一句话。两种都可以有效，前提是你知道自己属于哪一种，并确认自己的学习方式与之相容。需要高频纠偏的同学，进入低频反馈的环境，证据链容易在第一年就散掉。

### 四个坑

坑一，方向错配。你想做系统与评测，组里的公开工作却长期集中在另一类问题上。错配会让你的三年证据链长成别人的形状。纠正方法是先用公开材料做主题聚类，再决定是否申请。聚类时写下十个关键词，看自己是否真的愿意在这些词里工作三年。意愿来自任务，来自你愿意反复做的那种失败。

坑二，把论文压力直接等同于训练质量。有压力可以出活，也可以只出数量。质量的观察点仍是方法是否可复现、贡献是否可切分、失败是否可讨论。压力是环境参数，训练质量是过程参数，两者需要分开看。一个可操作的问题是：组里最近一次公开工作的评测协议，学生能否独立复述。能复述，压力才可能转化为训练；复述不出，压力只转化为焦虑。

坑三，资源口头化。算力、数据、标注预算、工程支持，口头承诺在入学后常常对不上。可核验的做法是问清：公共集群如何申请、学生个人额度如何管理、外部云资源如何报销、数据能否带出实验室用于自己的复现实验。具体数字以实验室与学校信息化部门的现行规定为准，本文不编造配额。资源问题要问流程，问队列，问失败时找谁。流程清楚，资源即使紧张，你仍能规划实验；流程不清楚，资源承诺无法进入你的计划。

坑四，把导师时间的不确定性当成自由。自由若伴随检查点、代码评审和书面反馈，能长出独立研究者；若只伴随沉默，长出的是无人阅读的仓库。你要的是可预期的反馈，而不是情绪上的被关注。入组前可以请求旁听一次公开组会或阅读一份已发表工作的附录，从中观察讨论是否触及方法细节。

四个坑之外，还有一个伴随风险：用名气替代核验。名气是公共信息，核验仍要回到方向、训练、资源、时间四件事。名气可以帮助你打开主页，主页上的公开材料才是证据。

| 观察项 | 可核验动作 | 把气氛当证据时的表现 |
| --- | --- | --- |
| 方向 | 近两年公开论文与代码的主题列表 | 我们什么都做 |
| 训练 | 学生能否讲清基线、消融、失败 | 我们氛围很好 |
| 论文节奏 | 工作是否有评测协议与复现物 | 每年都要有产出，这句话本身被当成方法 |
| 资源 | 申请流程、队列、数据使用边界 | 到时候会有卡 |
| 导师时间 | 反馈周期、合作导师、书面记录 | 老师很忙说明很厉害 |

假设你在联系实验室，过程为示意：先读三篇公开论文，各用半页写下问题与评测；再克隆一个公开仓库，按 README 跑通最小实验或记录跑不通的原因；然后把这两份笔记发给在读同学请教「这是否像组里的日常」。这一套动作的产物，本身就是你申请材料里的证据链雏形。

选组是双向的。实验室也在看你能不能把已有课程作业写成可核验片段。所以选组与后面的课程、大作业、科研是同一条链上的不同节点，顺序可以有交叉，标准不要改。推免、统考、博士申请的材料格式与截止时间，以各校研究生院当年通知为准，本文不编造时间表。

与老师通信时，证据语言同样适用。与其只表达仰慕，不如附上一页你对组里公开工作的问题定义复述，外加你能在入学前完成的最小实验计划。一页纸要包含：你读懂的问题、你的疑问、你打算复现的最小步骤、你需要的数据或算力边界。这样的邮件让对方用很低成本判断训练成本。具体联系方式以实验室主页为准。

## 四、本科与硕士课程：哪些先修，哪些可后置

课程是证据链的骨架材料。骨架的作用是让后面的项目、论文、实习有共同语言。先修与后置的划分，依据的是「后续几乎所有工作都会用到」还是「可在具体方向上再补」。各校培养方案、学分与开课学期以学校教务系统为准，下面只给能力顺序，不冒充某校课表。

### 建议先修的能力

线性代数。向量空间、矩阵分解、特征值与特征向量、正交与投影，是理解嵌入、注意力、主成分、最小二乘的共同底座。先修的目标不是背公式，而是能把一次线性变换说回数据上的操作。一个可用的自检：给你一个词向量矩阵，你能否说明降维、相似度和投影分别在做什么。

概率与统计。条件概率、贝叶斯、常见分布、期望方差、假设检验、最大似然。生成模型的采样、评测里的置信、对照实验的解读，都落在这里。缺了它，你只能把指标当运气。自检：你能否解释准确率与召回率在类别不均衡时为什么会打架，能否说明一次提升可能来自划分泄漏。

机器学习。训练、验证、测试的划分，过拟合，正则，偏差与方差，特征与模型的职责边界。公开课程与经典教材都在反复讲同一件事：先有协议，再谈模型。这门课的证据不是期末分数本身，而是你是否留下带基线的作业仓库。

编程、数据结构与算法。能写可测试的代码，能估计复杂度，能读懂别人的训练循环。语言可以是 Python 为主，后续再补系统语言。先修的是工程卫生：版本控制、依赖锁定、单元测试的最小习惯。没有卫生习惯，后面所有「项目」都会在交接时崩溃。

### 建议紧随其后的能力

深度学习。反向传播的计算图直觉、归一化、残差、正则与优化器的使用边界。先把「能训练并解释一条曲线」做扎实，再进入很大的网络。曲线解释包括：损失下降但验证变差说明什么，学习率过大时损失震荡说明什么，数据增强前后失败样本如何变化。

数据库与数据系统。SQL、索引、事务、数据清洗与血缘。检索增强、特征平台、评测集管理，最后都要碰到数据系统。很多所谓模型问题，其实是表没设计好、口径每次都重来。能把评测集放进带版本的表，你就已经比只会调参的同学更接近工业现场。

计算机系统基础。进程、内存、网络、并发、性能剖面。你不一定要做系统方向，但实习和转正后的值班，会惩罚完全不懂延迟与资源的人。系统课的证据可以很小：给自己的推理脚本加一次耗时分解，指出等待发生在哪一段。

### 可以后置、按方向再补的能力

自然语言处理或计算机视觉的专题。在机器学习与深度学习站住以后，再进入序列标注、检测分割、多模态对齐等专题，效率更高。专题课的正确用法是产出带评测的课程项目。过早进入专题，容易收集名词，却缺少划分与指标语言。

高级机器学习理论、因果推断、最优化专题。对研究导向有用，对多数应用岗可以按需后置。后置不等于永远不学，而是等你有具体问题再深入。有了具体问题，理论课会从抽象变成工具；没有问题，理论课容易变成新的清单。

编译、操作系统内核、分布式系统深水区。系统方向必补；应用方向在你真的要做训练框架、推理服务、集群调度时再加码。加码的信号是：你已经在自己的项目里碰到了内存、队列、一致性或调度问题，并且能用证据描述它。

| 课程族 | 建议位置 | 它在证据链里的作用 | 后置过久的代价 |
| --- | --- | --- | --- |
| 线性代数 | 先修 | 能解释嵌入、投影、分解 | 后续只能把矩阵当黑箱 |
| 概率统计 | 先修 | 能解释指标与不确定性 | 评测讨论停留在感觉 |
| 机器学习 | 先修 | 划分、基线、过拟合语言 | 深度学习课听成调参玄学 |
| 编程与数据结构 | 先修 | 可测试、可复现的代码 | 仓库无法交接 |
| 深度学习 | 紧随 | 训练循环与失败诊断 | 只能调用封装 |
| 数据库 | 紧随 | 评测集与特征可管理 | 数据口径每次都重来 |
| 系统基础 | 紧随 | 延迟、内存、并发语言 | 值班时无法定位 |
| NLP 或 CV 专题 | 可后置 | 方向证据 | 过早进入会缺评测语言 |
| 理论专题 | 可后置 | 研究深度 | 过早进入会缺工程证据 |
| 分布式与内核 | 按方向 | 系统岗证据 | 应用岗可延后 |

假设一位跨专业同学，经历为示意，在十二个月内只做四件事：线性代数与概率同步补课；用一门机器学习课交出带基线的作业；把深度学习课作业写成可复现仓库；用数据库课把评测集放进带版本的表。这四件事构成的骨架，已经够支撑后面的实习项目。骨架的检验标准很具体：你能否在白板前不看笔记，讲清一次训练的数据流与一次评测的定义。

课程成绩是学校官方记录，属于可核验证据的一种。它证明的是完成度，证明不了你能在脏数据上做决策。所以课程必须通过大作业，才能从成绩单走进简历。先修课若学校尚未开设，可用公开教材与公开课程补，但补课同样要留下作业仓库，否则只是又一份清单。

关于「要不要刷题」。算法题训练的是面试中的沟通速度与基本功，它是证据链的旁支。旁支可以服务主链：你在实现评测脚本、数据管道、服务接口时用到的结构与复杂度直觉。把刷题当唯一主业，主链会停。把刷题当每周固定的短训练，主链可以继续走。具体笔试形式以用人单位当年安排为准。

## 五、课程大作业如何写成产品证据

大作业的原始形态通常是：一份报告、一份笔记本、一个勉强可运行的训练脚本、一次课堂展示。产品证据的形态是：有用户、有约束、有评测、有复现、有失败样本。转化的关键是加一层交付约束，工作量往往小于再换一个更大的模型。

### 从作业到证据的六步

第一步，写用户与场景。即使是课程虚构用户，也要写清谁在什么时候用、用错的代价。假设，示意：助教需要在答疑时段过滤重复问题，用错会导致截止日期被误报。

第二步，钉死接口。输入字段、输出 schema、超时、拒答。接口比模型稳定，面试时也好画在白板上。接口一旦稳定，模型可以替换，证据链仍然连续。

第三步，先做非机器学习基线。规则、关键词、检索、正则。基线让你的提升有对照。没有基线的「准确率」，面试官会默认你把简单样本当成了成就。

第四步，建最小评测集。从作业数据里划出固定子集，标注标准答案或可接受集合。规模可以小，协议必须硬。协议要写清：如何划分、谁标注、如何处理歧义、是否允许从测试集调参。

第五步，把演示改成可回放。录屏、日志、一次失败的输入。演示当天的惊艳，三周后要能回放。回放材料也是转正后写故障演练的预习。

第六步，写已知限制。哪些输入会失败、数据有没有泄漏风险、模型输出有没有被当成官方承诺。限制写清楚，对方会认为你能进生产环境；限制藏起来，对方会在深挖时失去信任。

转化前后的对照如下。

| 大作业原件 | 产品证据加的一层 | 面试可追问点 |
| --- | --- | --- |
| 分类准确率数字 | 指标定义、划分、混淆矩阵、失败三类 | 你如何防止测试泄漏 |
| Jupyter 笔记本 | 脚本化入口、依赖锁定、种子 | 我如何在另一台机器跑 |
| 模型对比表 | 每次只改一个变量的记录 | 提升来自数据还是模型 |
| 课堂演示 | 录屏加失败输入回放 | 现场卡死你怎么排 |
| 实验报告感想 | 边界与下一步不做 | 你如何决定停手 |
| 课程数据集 | 数据来源、许可、脱敏说明 | 这段数据能不能进公司仓库 |

假设，示意：你的深度学习课要求在公开图像数据集上做分类。作业原件是准确率曲线。写成产品证据后，你可以补充：类别不均衡时的指标选择、一份二十张失败图像的错误类型表、一次把验证集混进训练的事故及修复、推理脚本的延迟测量方法。具体硬件与数字以你的实验记录为准，本文不编造。面试官问「你还做过视觉吗」，你递出的是协议与失败类型，而不是网络名称。

小组作业必须把贡献切分写到动作。谁做数据、谁做训练、谁做展示，写进 README 的作者段。切分含糊的作业，到科研和实习会继续含糊。如果历史作业已经无法改仓库，可以另写一页「事后切分说明」，诚实标出记忆不确定的部分。诚实本身是证据。

大作业还适合练习合规最小动作。即使是课程数据，也要写来源与许可，避免把含个人信息的样本提交到公共仓库。中国境内若涉及面向公众的生成式服务，还须了解《生成式人工智能服务管理暂行办法》等公开法规的基本要求，具体条款以官方原文为准。课程作业通常达不到「向公众提供服务」的阈值，养成标识、脱敏、日志留存的习惯，对实习同样有用。

《礼记·中庸》讲「博学之，审问之，慎思之，明辨之，笃行之」。大作业的笃行，就是把报告里的句子，落实成仓库里能跑的命令。

一个可执行的「作业产品化检查」可以在提交前两天做完：README 是否让陌生人十分钟内跑通最小路径；评测脚本是否只依赖锁定的数据版本；失败样本是否至少三类；贡献切分是否细到文件或提交；演示是否另存录屏。五条里缺两条，就还是作业；五条齐，才开始像产品证据。

## 六、科研：复现、负结果、贡献切分

科研证据最容易写成会议名清单，也最容易在深挖时空洞。可核验的科研证据，仍然落在五段链上，只是问题来自文献，结果可能是论文、技术报告或内部可复现实验。

### 复现是科研训练的入门动作

复现一篇公开论文，目标是学会作者的问题定义与评测协议，并留下你自己的实验日志。合格的复现记录包括：论文题目、作者、年份、会议或期刊、你使用的代码来源、你改动了什么、你的环境、你得到的指标范围、与论文表格不一致的地方、你认为不一致的可能原因。指标不一致很常见，原因可能是数据版本、随机种子、实现细节、硬件。把不一致写清楚，本身就是能力。

复现时请遵守学术规范：引用原作，不把原作者的图表改头换面当成自己的创新，不把未授权的数据再分发。会议与期刊的伦理政策以各会议官网为准。推荐的公开起点包括经典方法论文，例如 Vaswani 等人 2017 年的 Transformer、Lewis 等人 2020 年的 RAG、He 等人 2016 年的残差网络。选哪一篇，取决于你的方向，不取决于热度。

复现的交付物建议分三层。第一层，跑通作者或第三方公开实现的最小例子。第二层，在自己的划分上复现关键表格的一列。第三层，做一个你自己的失败分析：哪类样本系统性失败。第三层开始像研究，前两层是训练。很多人停在第一层，却在简历上写「复现了某某」。请把层级写进日志，面试时按层级讲。

### 负结果是一等证据

一次按协议完成、结果不支持原假设的实验，对训练的价值往往高于一次说不清的所谓成功。负结果要写：假设是什么、协议是什么、结果是什么、你排除了哪些实现错误、你因此放弃了什么。实验室若不允许公开负结果，可以写进内部实验日志，面试时用「我做过一次失败的消融，结论是某某模块在该数据上无增益」来讲，仍然可追问。

负结果需要协议完整，才配称为证据。少跑几个随机种子、评测脚本有缺陷、训练集混进测试集，这些是实现错误，需要先排除。你应当先做实现自检，再宣布假设不成立。自检清单可以很短：种子是否固定、划分是否泄漏、指标是否与论文定义一致、基线是否被公平对待。

### 贡献切分必须细到动作

「参与某某课题」是清单语言。「我维护评测集版本、实现对照模型的训练脚本、撰写实验某一节的消融表格、在投稿前复核随机种子」是证据语言。切分的原则是：另一作者看到这段文字，会承认这是你做的。通讯作者与学生作者的署名规范，以目标期刊会议指南及实验室内部约定为准，本文不讨论作者排序的非公开做法。

| 科研动作 | 可放入证据链的产物 | 切分时要避免的写法 |
| --- | --- | --- |
| 文献复现 | 复现日志、差异分析、补丁 | 我复现过很多论文 |
| 数据工作 | 标注规范、质检抽样、版本号 | 我做了数据 |
| 方法实现 | 模块提交哈希、对照表 | 我提出了新方法，但无对照 |
| 评测 | 协议文档、失败样本库 | 效果达到一流 |
| 写作 | 你撰写的章节与图表编号 | 论文是我们一起写的 |
| 负结果 | 假设、协议、结论三行 | 把失败藏起来 |

假设，示意：你的名字出现在一篇工作的作者列表中。面试前你应当能独立讲述：问题来源、你负责的模块、一条关键对照实验、一个你坚持要保留的失败讨论、一个你明确没有贡献的部分。最后一项尤其重要，它证明你尊重边界。

科研与就业的衔接点是：论文是结果的一种发表形式，评测协议与复现代码才是可迁移的能力。有的同学有论文但讲不清协议，有的同学暂无论文但有完整复现与负结果日志。后者在应用岗面试里常常更稳。是否需要论文，以目标实验室、院校培养方案或用人单位岗位说明为准，本文不给出必须几篇的配额。

读文献也要留下证据。推荐用固定模板记笔记：问题、数据、基线、指标、关键假设、可复现性、我能做的下一步。十篇有模板的笔记，胜过五十篇只有高亮的 PDF。笔记可以是私人的，面试时你能根据笔记把一篇工作讲到评测层面，就已经和「我读过很多」区分开。

## 七、实习：评测能力、工程能力、沟通记录

实习是证据链第一次接受工业约束的地方。约束包括：期限、代码规范、数据权限、值班、文档、与产品或业务方的沟通。实习要积累的三类证据，正好对应组里每天发生的事。

投递实习时，岗位职责、工作地点、薪资、转正可能性一律以用人单位招聘官网和录用通知为准。本文不编造名企名单、不编造内推成功率、不编造月薪。你能控制的是材料是否可核验。

### 评测能力

入组后尽早问清：线上或离线的金标准在哪里、指标如何定义、谁有权改评测集、一次指标波动如何归因。你能做的最小贡献，往往是把评测跑通并留下一次复现记录，或补一组失败样本。评测能力的外在表现是：你改动模型或提示之后，知道该看哪张表，知道什么情况下不该发布。

评测能力还包括拒绝错误指标。如果业务要的是「少把退款单分错」，你却只优化总体准确率，这是评测失配。能指出失配并提出切片指标，是实习中非常值钱的沟通。切片可以按类别、按来源、按长度、按是否含个人信息来做。具体怎么切，取决于业务，取决于你能拿到的权限。

涉及线上流量、用户数据、付费接口时，严格按公司安全规范执行。未经授权的数据不得带出，不得写入个人仓库。能讲方法就讲方法，不能讲细节就明确说不能讲。尊重保密，本身是合规意识的证据。

### 工程能力

工程证据看你是否把研究脚本变成可运行服务的一部分：配置与代码分离、日志字段稳定、超时与重试、幂等、回滚、代码评审意见的落实。你也许只改了一个函数，但你能讲清这个函数在请求链路上的位置，以及它失败时用户看见什么。

假设，示意：你为检索服务增加了超时。证据包括：变更说明、超时值的选择依据、一次回放日志、回滚步骤、对下游生成质量的影响评估。超时值本身会随系统改变，本文不给出所谓行业标准毫秒数。工程能力的面试表达，尽量画链路：请求进入、检索、生成、校验、返回，你的改动在哪一格，失败如何被看见。

### 沟通记录

沟通记录是最被低估的实习证据。周报、设计评审纪要、事故复盘、需求确认（注意脱敏）证明你能把不确定变成可执行的下一步。面试里「你如何处理需求冲突」这类问题，最好的答案是指向一次真实记录：你问了什么、对方如何确认、你如何写进文档。

| 实习周次，假设节奏 | 评测上可留下的 | 工程上可留下的 | 沟通上可留下的 |
| --- | --- | --- | --- |
| 第 1 至 2 周 | 跑通现有评测，记下环境坑 | 本地能启动服务 | 术语表、权限申请记录 |
| 第 3 至 5 周 | 补失败样本或切片指标 | 一次小变更合入主干 | 设计评审的问题清单 |
| 第 6 至 8 周 | 一次对照实验 | 超时、日志或降级 | 周报里的风险与依赖 |
| 第 9 周及以后 | 发布门槛讨论 | 值班或回滚演练 | 复盘与交接文档 |

上表是假设的节奏，真实实习长短与内容以用人单位安排为准。它的用处是提醒你：每周结束时问自己「这周的证据落在哪一格」，空白格就是下周的目标。

实习结束时，一份可带走的材料包，在公司允许的范围内，建议包括：你的公开可讲项目描述、脱敏后的评测协议要点、你提交的文档编号、一次复盘的结构。材料包先给导师过目。涉及内部数据、未公开模型、客户信息的内容，一律按保密协议处理。

实习周报可以按证据链写，避免写成流水账。建议四段：本周闭合的问题、方法上的决策、结果与风险、下周需要他人确认的事项。四段周报在转正面试时几乎可以直接改写成项目叙述。流水账周报只能证明你在线打卡。

## 八、开源与比赛：何时加分何时浪费时间

开源与比赛能加速证据链，也能打断证据链。加分的条件是：它们产出可核验的问题、方法、结果、复现、反思。浪费时间的典型情况是：只刷热度、只改排行榜数字、只提交无法说明的笔记本、把队友的工作写进自己的简历。

### 开源何时加分

加分的开源通常满足至少两条：你解决了真实使用者的问题，例如 issue、文档、复现脚本、测试；你的提交可被独立核验，例如 pull request 讨论、评审意见、回归测试。文档修补、最小复现、评测脚本、类型标注，这些工作往往比一次无测试的巨型重构更经得住问。

选择仓库时，看维护是否活跃、贡献指南是否清楚、许可是否允许你的使用方式。许可与贡献流程以各项目官方文件为准。许可决定你的代码能否进入公司产品，也决定你能否把截图放进简历。不清楚许可就公开拷贝，会把合规风险带进求职。

开源贡献的叙述应指向一次具体提交。写清：问题编号、你的复现步骤、补丁做了什么、测试如何证明、维护者问了什么你如何改。一串仓库星标截图，核验成本高，信息量低。

### 比赛何时加分

比赛加分，当你能讲述：任务定义、数据使用规则、验证策略、防止泄漏的方法、一次无效的尝试、最终方案相对基线的增益来自哪里。名次是结果的一种，协议才是能力。主办方规则、奖金、证书以赛事官网为准，本文不转述具体奖金与排名。

数据比赛最常见的时间浪费是泄漏驱动的名次。把测试分布的信息通过频繁提交「试探」出来，名次上升，方法不可迁移。面试官若问验证策略，泄漏路径会暴露。宁可名次普通但验证闭合，也不要无法解释的榜上数字。

黑客松容易只留下气氛。请在结束当天把录屏、已知问题、分工说明写进仓库。评委记住的是演示，你求职需要的是仓库。两者都要。

| 投入类型 | 容易留下的证据 | 容易变成浪费的走法 | 建议的停手条件 |
| --- | --- | --- | --- |
| 给文档补最小复现 | 合并记录、issue 关闭记录 | 只提意见不给补丁 | 维护者明确不接受该方向 |
| 给评测加失败样本 | 测试用例、回归记录 | 只吐槽模型差 | 样本无法脱敏公开 |
| 个人工具库 | README、示例、版本 | 只有自己能跑 | 三个月无人包括你自己使用 |
| 数据比赛 | 验证策略、泄漏排查 | 只追公开榜 | 验证集策略已经不可解释 |
| 黑客松 | 录屏、评测、分工 | 只合影与奖状 | 结束一周仍无仓库说明 |
| 论文复现挑战 | 差异日志 | 只宣称复现成功 | 无法指出与原论文的差异 |

假设，示意：你用两个周末给某个检索库补了一份中文最小示例和一篇常见失败说明。这比你同时关注二十个大模型仓库更接近证据。开源名单的长度，面试官可以一眼看穿；一条被合并的、带测试的提交，可以追问半小时。

时间是有限的。开源与比赛要服务主证据链：实验室方向、实习目标、求职岗位说明书上的技能。三者同时发散时，选能在本学期闭合五段链的那一件。学期中途切换赛道，旧链未闭合、新链未开始，简历上只会多一行无法深挖的名词。

比赛与开源的学分、奖金、升学加分政策因学校而异，以教务处、研究生院和主办方文件为准。不要把民间传闻写成你的规划依据。

## 九、简历结构：链接、日志、评测表、录屏

简历是证据链的索引，不是证据链本身。索引的任务是让核验者在三十秒内知道该点开哪四个对象：项目链接、实验日志、评测表、演示录屏。四个对象不必都公开到互联网，但你必须在面试时能调出。内部材料按保密协议处理，可用脱敏版本或现场演示替代。

### 结构建议

页眉只放能被联系到的信息：姓名、邮箱、个人主页或仓库总览、教育经历。教育经历写学校官方名称、专业、在读或毕业时间，以学籍或学历证书为准。不要在页眉堆模型名。

项目条目建议固定四行。第一行：任务一句话。第二行：方法中的关键决策与基线。第三行：结果，带协议提示，数字若不便公开就写「详见评测表」。第四行：链接，指向仓库、日志、评测、录屏中你真正准备好的那些。四行写不满的项目，考虑从简历拿掉。

科研条目同样四行，把会议名放在结果行，不要放在第一行。第一行仍是问题。会议名、接收状态以出版社或会议官方系统为准，避免把「在投」写成「已发表」。

实习条目突出你的可移交产出：合入的变更类型、评测改进、文档、值班。公司名称与职位以劳动合同或实习证明为准。不要写无法核验的「核心参与」。

| 简历模块 | 建议承载的证据 | 建议删除的内容 |
| --- | --- | --- |
| 页眉 | 联系方式、主页、学籍信息 | 模型名串、薪资预期编造 |
| 教育 | 官方专业名称、关键课程项目链接 | 自行发明的方向头衔 |
| 项目 | 四行结构加四类链接 | 无仓库无评测的形容词 |
| 科研 | 问题、贡献切分、公开编号 | 把在投写成已发表 |
| 实习 | 可移交产出与文档 | 无法脱敏的内部指标 |
| 开源比赛 | 具体提交或方案说明 | 只含名次的一行字 |
| 技能 | 能当场演示的工具 | 用过一天的框架清单 |

链接要可点、可运行、可定位到提交。过期链接等于没有链接。建议在投递前用无痕模式打开每一个 URL。日志建议按时间倒序，至少保留关键实验的配置与结果。评测表建议用表格而不是截图里的曲线，表格能被追问到单元格。录屏建议控制在三到五分钟，包含一次成功路径和一次失败路径。

简历长度服从核验。一页或两页都可以，前提是每一项都能被深挖。两页但充满空洞形容词，核验成本高于一页实的。中英文简历内容应一致，翻译不是另写一套故事。

假设，示意：一位同学把「智能客服大模型系统」改写成「工单五分类，规则基线之后加入检索与生成，评测集五十条脱敏样本，幻觉定义为文档外日期，仓库含复现命令与失败日志」。改写后字数下降，可追问点上升。这就是简历作为索引的正确方向。

投递前请做一次「陌生人测试」：把简历和链接发给一位不在项目里的同学，请对方只根据材料写出你的问题、方法、结果。对方写错的地方，就是索引失败的地方。修正索引，再投。

涉及个人信息的简历存放与传输，遵守《个人信息保护法》的最小必要原则。不要在公开网盘裸放身份证、学生证扫描件。招聘方若要求证明材料，走对方官方渠道。

## 十、面试：项目深挖、系统设计、安全与合规意识

面试是现场核验。核验通常沿三条线前进：项目深挖、系统设计、安全与合规。三条线都指向同一问题：你能否在约束下做可移交的决定。

### 项目深挖

深挖的典型路径是：你简历上的一句话，被要求展开成五段链，再被要求在白板上画出数据流，再被要求解释一次失败。准备方法是把自己当面试官，对每个项目预先写二十个追问。追问要覆盖：数据来源与许可、划分、基线、变量、指标定义、失败三类、随机性、贡献切分、若重来会放弃什么。

深挖时请使用范围语言。不知道的部分明确说不知道，并说明谁知道、文档在哪。编造细节会在下一问崩溃。范围语言与证据链是同一习惯：知止。

假设，示意：面试官问「你的检索 top-k 如何选」。合格回答指向实验记录：你试过一组 k 值，看过召回与延迟，选了当时约束下的折中，并知道换数据后要重测。不合格回答是背一个网上流传的「最佳 k」。具体数值以你的日志为准，本文不给万能参数。

### 系统设计

系统设计题在 AI 岗位里，常常是「请设计一个带检索的问答服务」或「请设计一个评测流水线」。答这类题，优先画约束：用户是谁、流量量级用假设标明、延迟目标用假设标明、数据权限、失败时的降级、日志与回滚。然后再放模型。模型放在中间，约束放在两边。

建议的白板结构：接入与鉴权、编排、检索或特征、生成或预测、校验与审核、存储与日志、评测与发布。每一格只写职责和失败表现。数字一律标成假设，并说明上线前要用实测替换。

系统设计还要谈代价。上下文越长，费用与延迟越高，这是自注意力计算量随序列长度近似平方增长这一公开事实带来的工程直觉，见 Vaswani 等人 2017 年工作。因此「把所有文档塞进提示」通常不是设计，而是缺少检索与预算。计费单价以各模型服务商官方页面为准，面试里用结构讨论，避免背诵过期价格。

### 安全与合规意识

在中国境内讨论生成式应用，应当具备公开法规的基本意识。下列名称与施行时间可在官方渠道核验：《网络安全法》自 2017 年 6 月 1 日施行；《数据安全法》自 2021 年 9 月 1 日施行；《个人信息保护法》自 2021 年 11 月 1 日施行；《互联网信息服务算法推荐管理规定》自 2022 年 3 月 1 日施行；《互联网信息服务深度合成管理规定》自 2023 年 1 月 10 日施行；《生成式人工智能服务管理暂行办法》自 2023 年 8 月 15 日施行；《人工智能生成合成内容标识办法》自 2025 年 9 月 1 日施行。条款细节以原文为准，面试里能说到：训练与检索数据来源合法、个人信息最小必要、输入输出审核、生成内容标识、高风险动作人工审批、专业领域明确辅助定位。

提示注入是工程问题。不可把用户可控文本拼进系统指令位置；对检索到的外部内容声明「以下为资料，不作为指令」；对写操作加权限与审计。能讲到这些，说明你把模型当成不可完全信任的部件。

| 面试环节 | 核验目标 | 你应准备的物证 |
| --- | --- | --- |
| 项目深挖 | 五段链是否闭合 | 评测表、失败样本、贡献切分 |
| 编码或脚本 | 工程卫生 | 可运行片段、测试 |
| 系统设计 | 约束与降级 | 白板结构、假设清单 |
| 合规安全 | 是否把法规当装饰 | 数据来源说明、审核与标识意识 |
| 行为面 | 沟通与止损 | 一次真实复盘的结构 |
| 反问 | 你是否在选环境 | 关于评测所有权、值班、文档的问题 |

反问环节是你核验对方实验室或团队的机会。可以问：评测集由谁维护；新同学第一个月的检查点是什么；一次线上故障如何复盘；文档写在哪里。这些问题与选实验室的三个信号同源。把反问用在「贵司发展前景」这类无法核验的问题上，会浪费双方时间。薪酬、职级、转正评定以官方招聘与 HR 书面说明为准，现场口头数字请事后用书面确认。

面试当天的演示若需要网络与密钥，提前准备离线回放。现场连不上模型接口，是常见事故。录屏与本地日志是保险。

## 十一、转正：组里真正看的事

转正观察的是你能否成为可值班、可交接、可协作的同事。模型名在转正讨论里权重继续下降。组里真正反复出现的四件事是：交付、值班、文档、协作。

交付。按约定的范围与时间交出可运行的增量，并附上如何验证。交付的质量看是否需要别人替你补测试、补文档、补回滚说明。一次范围变小但验证完整的交付，优于范围很大但无法验证的演示。

值班。能否在告警出现时按手册定位，而不是凭感觉重启。值班证据包括：你写过的排障记录、你补过的手册条目、你发起的一次复盘。即使实习期没有正式值班，也可以申请旁听一次故障处理，并写下自己的理解请同事纠正。

文档。文档是给六个月后的陌生人看的，包括未来的你。好文档有背景、步骤、已知失败、联系人。把文档当成作业报告来写，同事无法使用。把文档当成复现协议来写，组里会记住你。

协作。代码评审是否回应意见，需求变更是否书面确认，是否在阻塞时及时升级。协作的证据是记录，不是性格自评。性格自评无法核验，记录可以。

| 转正观察项 | 组里可看见的信号 | 仅有模型清单时的缺口 |
| --- | --- | --- |
| 交付 | 可验证的增量、明确的完成定义 | 只有演示日惊艳 |
| 值班 | 按手册定位、补手册 | 出问题只能找原作者 |
| 文档 | 陌生人能按步骤操作 | 知识留在聊天记录 |
| 协作 | 评审回应、升级及时 | 单打独斗且无法合并 |
| 评测纪律 | 指标下降不发布 | 凭感觉上线 |
| 合规 | 权限内工作、不带出数据 | 把内部样本拷到个人网盘 |

转正答辩或总结，建议按证据链写三页：你接手的问题、你留下的方法与文档、你参与的一次失败及修复、你尚未完成且已写进交接的事项。三页里避免形容词。转正名额、薪资调整、职级，以用人单位制度为准，本文不编造比例。

假设，示意：两位实习生都调过提示词。甲留下了提示版本、评测对比、回滚开关和一篇给下一任的说明。乙留下了聊天记录里的「效果更好了」。转正讨论里，甲的材料可以被没有参加过项目的人阅读。乙的材料只能由乙本人解释。组里要的是甲那种可离开现场仍然成立的证据。

转正之后证据链并未结束。它变成你在组内的信用记录。信用来自多次小而闭合的交付，来自你在文档和评测上的公共贡献。继续堆模型名，信用不会自动增长。

## 十二、跨专业转 AI 的补课顺序

跨专业转入人工智能相关方向，补课顺序服从先修逻辑，服从证据链闭合速度。目标是尽快拥有一个可核验的小项目，而不是尽快拥有一张新的名词表。原专业不是负债。原专业若提供领域问题，例如医学文本、工业质检、法律文书、教育评测，反而能成为问题段的来源。请把原专业写成问题，把 AI 写成方法。

建议顺序如下，时长为假设，因人而异。

第一阶段，编程卫生与离散基础。学会 Git、单元测试、读写文件与 HTTP 调用，补齐数据结构的常用部分。交付物：一个有测试的小工具仓库。

第二阶段，线性代数与概率的可运算理解。配合习题，把概念做到能解释一条训练曲线。交付物：用矩阵运算实现一个最小线性分类或回归，带评测。

第三阶段，机器学习协议。划分、基线、指标、过拟合。交付物：在一个公开表格数据集上的完整实验报告，规模可以很小。

第四阶段，深度学习最小闭环。一个分类或序列任务，脚本化，可复现。交付物：失败样本表。

第五阶段，系统与数据。SQL、简单服务、日志。交付物：把第四阶段的模型包成带超时与日志的接口。

第六阶段，方向专题。NLP、CV、推荐、智能体等，按你能接触到的领域问题选择一个。交付物：五段链齐全的项目，准备用于实习或考研材料。

| 阶段，假设 | 能力 | 交付物 | 常见提前跳级的后果 |
| --- | --- | --- | --- |
| 一 | 编程卫生 | 带测试的小工具 | 后续仓库无法复现 |
| 二 | 线代与概率 | 最小线性模型实验 | 深度学习课听不懂指标 |
| 三 | 机器学习协议 | 带划分的报告 | 只会调包 |
| 四 | 深度学习闭环 | 失败样本表 | 只会调用大模型接口 |
| 五 | 系统与数据 | 带日志的接口 | 实习无法值班 |
| 六 | 方向专题 | 五段链项目 | 简历只有课程名 |

跨专业考研的考试科目、参考书、分数线、名额，以目标院校研究生院当年招生简章为准。跨专业求职的岗位门槛，以用人单位招聘启事为准。任何人声称的「跨专业录取最低分」或「转行起薪」，若无法指向官网，都不要写进你的计划。

跨专业同学容易陷入两极：一极是无限补数学而没有项目；一极是只调接口而没有协议。证据链要求两端同时存在，但闭合顺序是先小项目后加深数学。数学深度可以随研究需求增长；没有项目，数学无法被核验为能力。

原专业的写作、实验记录、田野调查、工程图纸，都可以迁移为科研日志习惯。迁移时做一次翻译：把原专业的「材料与方法」对应到 AI 的评测协议，把原专业的「结果与讨论」对应到失败分析。你会发现证据链并非计算机系私有。

## 十三、时间线：大二到毕业的示意节奏

以下时间线全部为假设示意，用于帮助你把证据链摊到日历上。各校小学期、实习窗口、推免时间、秋招时间差异很大，必须以本校教务、研究生院和用人单位当年通知为准。不要把下表当成真实校历。

| 假设学期 | 主任务 | 应闭合的证据 | 建议暂缓的事 |
| --- | --- | --- | --- |
| 大二上 | 线代、概率、编程卫生 | 带测试的小仓库 | 同时追很多比赛 |
| 大二下 | 机器学习课与第一个评测作业 | 基线加划分加失败样本 | 过早锁定很窄的论文题目 |
| 大三上 | 深度学习课作业产品化 | 可复现仓库、录屏 | 用模型清单填简历 |
| 大三下 | 接触实验室或方向专题 | 一篇复现日志、一次组会提问 | 只旁听不留下笔记 |
| 大三暑假 | 第一次实习或开放课题 | 评测、工程、沟通三格各有记录 | 把保密数据带出公司 |
| 大四上 | 实习证据整理、科研或毕业设计开题 | 简历四类链接可点 | 新开无数仓库 |
| 大四下 | 毕业设计闭合、求职或升学材料 | 五段链终稿、交接文档 | 临门改题导致无法复现 |
| 硕士一年级 | 选组核验、复现训练 | 方向匹配笔记、负结果日志 | 只用名气选组 |
| 硕士二年级 | 主课题与实习之一闭合 | 贡献切分清楚的公开材料 | 并行过多导致段段断裂 |
| 毕业季 | 转正或求职答辩 | 可移交的文档与评测 | 把故事说得比仓库大 |

时间线的使用方法是：每个学期只选择一个主闭合目标。主目标完成前，其他活动只能当旁支。旁支服务主目标，例如为了毕业设计去比赛里借一个评测想法，可以；为了比赛把毕业设计停掉，主链会断。

大二就可以开始写实验日志，不必等到「有重大成果」。日志的早期价值是训练诚实：写清自己跑不通的原因。诚实的日志在申请实验室时非常加分，因为它证明训练成本低。

假设，示意：一位同学大三暑假实习只做了评测集切片和两篇文档，没有训练新模型。秋招时她能讲清指标失配如何被发现、如何改切片、如何阻止一次错误发布。这段叙述的强度，高于另一位同学暑假里调用了更多模型却讲不清评测。时间线考核的是闭合，不是热闹。

升学与就业并行时，材料可以共用五段链，封面不同。给实验室的版本强调复现与负结果；给用人单位的版本强调接口、值班与文档。共用证据，分别索引。两套完全无关的故事，会让你自己在面试里打架。

## 十四、十个证据链断裂案例

以下十个案例全部为假设示意，用于说明断裂发生在哪一段。它们不是对任何真实同学、实验室或公司的描述。读的时候请对照自己的仓库，看有没有同类缺口。

案例一，问题段缺失。同学实现了一个聊天机器人，简历写「基于大模型的智能助手」。面试官问用户是谁、成功标准是什么、拒答出口在哪。回答停留在「可以聊天」。断裂点：没有可观察任务。补救：用一句话写下用户、时限、标签或拒答、用错代价，再决定是否保留该项目。

案例二，方法段只有工具名。仓库依赖齐全，README 是框架官方示例的改写。面试官问基线是什么、为什么上检索、放弃了什么。回答是「大家都这么做」。断裂点：没有决策记录。补救：补一张对照表，即使对照是后补的，也要诚实标明后补。

案例三，结果段只有形容词。报告写「效果显著提升」。没有划分说明，没有指标定义，没有失败样本。面试官请对方现场定义幻觉，现场沉默。断裂点：数字没有协议。补救：哪怕评测集只有三十条，也把协议写死。

案例四，复现段名存实亡。链接指向私人笔记本，依赖未锁定，随机种子每次不同，数据路径写的是本人电脑用户名。核验者无法跑。断裂点：演示代替复现。补救：最小命令、环境文件、脱敏数据样例、已知失败列表。

案例五，反思段写成感想。结尾是「我收获很大，感谢队友」。面试官问下一步不做什么，没有答案。断裂点：不能止损。补救：列出失效数据分布、攻击面、明确暂缓的模块。

案例六，贡献切分崩溃。三人作业，三份简历都写「负责模型训练与优化」。对照 Git 记录，提交集中在一个人，另外两人主要改报告格式。面试对质后三条链同时失信。断裂点：署名与动作不一致。补救：按文件与提交写切分，不确定就写不确定。

案例七，保密边界被踩破。实习生把含用户信息的样本拷到个人网盘做「作品集」。即使模型效果可讲，合规已经失败。断裂点：证据取得方式非法或不被允许。补救：只带走方法描述与公开或授权数据上的复现，作品集先送审。

案例八，开源清单膨胀。简历列出十五个仓库的贡献者徽章，实际多为自动生成的拼写修正。面试官点开最大的一笔，发现与岗位无关且无测试。断裂点：用数量代替可核验提交。补救：留一到两项能讲半小时的贡献。

案例九，比赛名次无法解释。公开榜成绩看起来很好，验证策略是根据提交反馈调参。面试官问如何防止泄漏，路径被问穿。断裂点：结果依赖不可迁移的试探。补救：重写验证，接受名次下降，换可讲述的方法。

案例十，转正材料与实习现场脱节。总结写「独立负责智能体平台」，实际工作是改两处日志字段。同事无法在文档里找到所谓平台。断裂点：故事大于仓库。补救：按可验证增量重写，平台二字删掉，日志字段与手册条目留下。

十个案例的共同结构是：某一段被形容词替换，核验在该段停止。修复方法也共同：回到五段链，用最小交付物填上缺口，删掉填不上的名字。

## 常见弯路十则

弯路与断裂案例相邻，但更偏长期习惯。下面十条在升学与秋招咨询里反复出现，表述为可改正的走法。

弯路一，用关注列表代替动手。每天收集模型发布，仓库仍空。改正：每周只闭合一个最小实验，发布信息改到周末一次性阅读。

弯路二，把实验室名气当方向。入学后发现任务家族自己并不愿意反复失败。改正：用近两年公开材料做主题聚类，再投递。

弯路三，课程只追高分，作业仓库从不整理。成绩单好看，面试无法核验。改正：每门核心课留一个可跑仓库。

弯路四，未做基线就上大模型。任何提升都无法归因。改正：规则或线性模型先跑通。

弯路五，评测集随手改，指标永远上升。改正：评测集版本化，改协议必须记录。

弯路六，同时开五个方向的专题。每个方向都有半成品。改正：一学期一个主闭合目标。

弯路七，把刷题当求职全部。算法通了，项目深挖失败。改正：刷题当旁支，主链仍是可运行证据。

弯路八，把内部指标写进公开简历。既有泄密风险，又无法被外部核验。改正：写方法与公开协议，内部数字留在现场经授权再讲。

弯路九，等待「准备好了」再联系实验室或投实习。准备好的定义变成永远做下一项课程。改正：用最小复现笔记作为第一封邮件附件。

弯路十，把转正当成表演周。前几个月松散，最后两周补材料。改正：每周填评测、工程、沟通三格，转正材料只是汇总。

| 弯路 | 表面收获 | 证据链上的损失 | 改正动作 |
| --- | --- | --- | --- |
| 只收集发布信息 | 显得很新 | 没有可跑对象 | 每周一个最小实验 |
| 只追名气 | 申请看起来安全 | 方向错配 | 主题聚类后再投 |
| 只追成绩 | 绩点好看 | 作业无法核验 | 每门课一个仓库 |
| 不做基线 | 很快有演示 | 无法归因 | 先规则后模型 |
| 改评测集 | 指标上升 | 协议失效 | 版本化 |
| 多线半成品 | 简历行数多 | 段段不闭合 | 一学期一主目标 |
| 只刷题 | 笔试过关 | 深挖失败 | 旁支化 |
| 公开内部指标 | 看起来很工业 | 合规与核验双输 | 脱敏与授权 |
| 等待准备好 | 焦虑减少一时 | 窗口错过 | 最小笔记先发 |
| 表演式转正 | 总结很长 | 同事无法阅读 | 每周留痕 |

## 十五、二十问

下面二十问按「先核验材料、再核验路径」排列。答案服从本文原则：给方法，不编造分数、名额、薪资。

问一：简历技能栏到底写不写模型名？
答：可以写你真正能深挖的少数几项，并且每项都能指向项目里的方法段。技能栏是索引的索引，写多了会变成追问清单。

问二：没有论文能不能投 AI 实习？
答：能。许多应用岗更看评测、工程与文档。是否要求论文，以岗位启事为准。没有论文时，用复现日志与课程产品证据填上五段链。

问三：没有实习能不能投秋招？
答：能，难度在于核验物更少。用课程作业产品化、开源最小复现、毕业设计闭合来补。窗口与岗位要求仍以官网为准。

问四：GPA 低还有没有路径？
答：成绩是官方证据之一，低绩点会增加筛选阻力。你能做的是让项目证据厚到足以在面试阶段被核验。各校与各单位如何使用成绩，以官方说明为准。

问五：一定要进所谓名校实验室吗？
答：你要进的是方向匹配、训练可见、时间可预期的环境。校名是公共信息，训练过程才决定证据形状。具体院校选择结合培养方案与导师公开材料，不结合传闻排名。

问六：跨专业来不及补完数学怎么办？
答：按第十二节顺序先闭合小项目，数学随问题加深。先修中的线代与概率要达到能解释指标的程度，理论专题可后置。

问七：开源贡献少会被刷掉吗？
答：开源不是硬通货。一条带测试的提交，强过一串空徽章。没有开源也可以，用课程与实习证据。

问八：比赛一定要拿奖吗？
答：奖状是结果的一种。能讲清验证策略与失败尝试，比赛才进入证据链。奖项规则以赛事官网为准。

问九：如何证明贡献是我做的？
答：提交记录、文档作者段、可独立复述的模块、其他作者认可的切分说明。口说「主要是我做的」核验成本过高。

问十：数据不能公开，项目是不是作废？
答：公开的是方法、协议、脱敏样例或合成替代数据。保密部分现场经授权说明。项目可以保留，叙述必须守边界。

问十一：面试被问到不会的细节怎么办？
答：明确范围，指出文档位置或负责人，给出你将如何验证的下一步。编造细节会在下一问崩溃。

问十二：系统设计不会画怎么办？
答：从用户、权限、失败降级、日志回滚四条约束画起，再放检索与模型。约束比组件名重要。

问十三：要不要自学微调？
答：当任务风格固定、有标注、且提示与检索已经不够时再动权重。多数课程与实习场景，评测与检索的证据更先被需要。

问十四：如何选课才对求职有用？
答：先修线代、概率、机器学习、编程；紧随深度学习、数据库、系统；专题后置。对求职有用的是作业仓库，不只是课名。

问十五：导师很忙是不是一定很差？
答：忙是状态，可预期反馈才是训练条件。看检查点、合作导师、书面意见，看学生能否讲清评测。本文不对任何导师做评价。

问十六：转正答辩讲技术细节还是讲价值？
答：讲可验证的交付、值班、文档、协作，用业务语言解释这些交付减少了什么失败。价值若不能指向物证，会变成形容词。

问十七：应届生要不要谈薪？
答：薪酬以用人单位书面 offer 为准。面试阶段先核验工作内容与评测环境。口头数字事后用书面确认。本文不提供薪资数字。

问十八：如何避免把内部代码当作品集？
答：入职与离职都读保密协议。作品集只用授权材料、公开数据与方法描述。拿不准就问导师和法务，默认不带出。

问十九：一个月能准备好秋招吗？
答：一个月够闭合一项小而完整的五段链，并整理已有仓库的链接与评测表。不够同时从零学会全部专题。把范围变窄。

问二十：证据链是不是只对大厂有用？
答：任何需要交接的团队都需要可核验材料。实验室、中小公司、研究组、公务与事业单位的信息化部门，差别在领域约束，不在是否需要证据。岗位性质以官方招聘为准。

## 十六、结语

秋招与升学看起来像两场不同的考试，对 AI 方向的同学却共用同一条链。链的名字叫证据：问题、方法、结果、复现、反思。模型清单可以当目录，目录不能当证明。

从实验室到转正，环境在变，标准稳定。选组看方向、训练、时间、资源是否可核验；上课看先修是否撑得住评测语言；作业要加成产品约束；科研要写清复现、负结果与切分；实习要留下评测、工程、沟通；开源与比赛要能停手；简历只做索引；面试接受现场核验；转正看交付、值班、文档、协作。跨专业的人用同一标准，只是补课顺序更需要克制。

《大学》的「知止而后有定」，落到这件事上，就是承认范围。承认自己只能闭合一条主链，承认数据不能公开时就讲方法，承认不会的细节就指向文档。止，不是停，是让下一步可执行。

如果只带走三句话：第一，简历上的每一项都要能指向可运行对象。第二，数字必须绑定协议，失败样本必须可展示。第三，涉及分数、名额、薪资、排名，回到学校与用人单位的官方页面，拒绝传闻。

> 博学之，审问之，慎思之，明辨之，笃行之。——《礼记·中庸》

下一篇材料，建议你打开自己的仓库，只做一件事：给目前最想写进简历的那个项目补齐五段链的最小交付物。补完，再决定要不要加新的模型名。

## 检查清单

把下面的清单贴在投递或开题前，逐条打勾。勾不完就先缩小范围。

- [ ] 每个简历项目都能用一句话说清用户、成功标准、失败代价。
- [ ] 每个项目都有基线，且对照实验一次只改一个变量。
- [ ] 评测协议写清数据版本、划分、指标定义、抽样与人工抽检。
- [ ] 至少三类失败样本可展示，并能对应到修复动作。
- [ ] README 提供最小复现命令、依赖锁定、随机种子、已知失败。
- [ ] 贡献切分细到动作，小组作业与论文均如此。
- [ ] 链接在无痕模式可打开，录屏包含成功与失败各一次。
- [ ] 实验日志按时间可检索，关键配置可回放。
- [ ] 数据来源与许可已写明，个人信息已按最小必要处理。
- [ ] 内部数据与代码未进入个人作品集，保密协议已遵守。
- [ ] 开源或比赛条目能指向具体提交或验证策略。
- [ ] 面试追问二十题已对每个主项目预写。
- [ ] 系统设计能从约束、降级、日志、回滚讲起。
- [ ] 了解生成式人工智能相关公开法规的名称与基本义务，细节将回查原文。
- [ ] 转正或交接文档包含验证步骤与联系人。
- [ ] 涉及招生分数、名额、薪资的数字均指向官网，简历中未编造。
- [ ] 本学期主闭合目标只有一个，旁支服务主目标。
- [ ] 陌生人根据简历能写出你的问题与方法，且基本正确。

## 术语表

**证据链：** 由问题、方法、结果、复现、反思五段构成的可核验叙述，服务于招生、招聘、同事与未来的自己。

**模型清单：** 以模型名称、参数规模或厂商发布为主要自我介绍的写法，缺少五段中的协议与失败分析。

**评测协议：** 关于数据版本、划分、指标、抽样与抽检的书面约定。没有协议的指标不能作为结果段。

**基线：** 在加入你的方法之前就存在的可运行对照，可以是规则、线性模型或公开实现。

**复现：** 他人按文档在声明的环境中重复关键实验或最小演示的能力，包括已知失败。

**负结果：** 在协议完整且实现自检之后，结果不支持原假设的实验结论。

**贡献切分：** 把署名翻译成可核验动作与文件，使其他作者能够承认。

**产品证据：** 在课程或科研产出上增加用户、接口、评测、复现、限制之后形成的可交付叙述。

**测试泄漏：** 测试或验证信息进入训练或调参过程，导致指标不可迁移。

**提示注入：** 通过用户或外部文本干扰模型指令，使系统偏离原定约束。

**值班：** 按手册响应告警、定位失败、升级与复盘的轮值工作。

**交接：** 让下一个维护者能够验证、运行与修改系统的文档与权限安排。

**方向匹配：** 实验室或岗位近两年公开任务家族与自己愿意反复失败的问题相一致。

**训练风格：** 组内如何传授方法、如何讨论失败、如何维护评测等可观察过程。

**知止：** 承认范围、拒答、停手条件与保密边界，使下一步可执行。

## 附录：公开资料核验方法

招生分数、复试名单、名额、推免办法、培养方案，请到目标学校**研究生院、招生办、教务处**的官方网站查询当年通知。不要使用来路不明的截图作为规划依据。网页更新频繁，本文不粘贴易失效的具体分数，也不保存过期表格。

岗位职责、工作地点、薪酬结构、实习证明要求、校招日程，请到用人单位**招聘官网**或官方授权的招聘平台查询。内推信息若无法回到官网岗位编号，视为传闻。转正评定以劳动合同与单位制度为准。

法规条文请到中国政府网、国家法律法规数据库、国家互联网信息办公室等官方渠道阅读全文。本文第八、十节列举的法规名称与施行日期，用于建立检索入口，执行以原文和主管部门最新解释为准。

论文与方法请回到出版社、会议官网或作者公开主页。推荐核验的公开起点包括：Vaswani 等 2017 年《Attention Is All You Need》；He 等 2016 年残差网络工作；Lewis 等 2020 年 RAG；Brown 等 2020 年少样本学习；Wei 等 2022 年思维链；Zheng 等 2023 年 LLM-as-judge。引用时写作者、年份、会议或期刊，避免只写俗称。

开源许可、贡献指南、安全策略，以目标仓库的 LICENSE、CONTRIBUTING、SECURITY 文件为准。比赛规则、数据使用协议、奖金，以主办方页面为准。

云算力价格、模型 API 单价、学生优惠、免费额度，均属易变信息，请以服务商官方计费页为准。本文不作记忆性转述。

教育部关于招生、学位、实习实践的政策文件，请在教育部官网政策文件栏目检索。学校如何执行，仍以学校文件为准。

核验的日常动作可以固定为三步。第一步，找到官方域名，而不是搜索引擎第一条广告。第二步，核对该页的发布日期是否覆盖你正在申请的年份。第三步，把链接与访问日期写进你的申请日志。日志让你在信息变化时能够解释自己当时依据的是哪一版。
